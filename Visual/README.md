# K210 视觉巡线模块 · 使用说明

K210 只负责"看"，看完把数字通过串口丢给 STM32；车怎么走全归 STM32 管。
**没有改动 `Control/` 下任何文件，也没有动 Keil 工程和 `.vscode`。**

---

## 一、文件怎么分工

| 文件 | 行数 | 只管什么 | 你什么时候动它 |
|---|---|---|---|
| `config.py` | ~95 | **所有数字和开关**，没有一行逻辑 | 调参只动这个 |
| `vision.py` | ~210 | 相机几何、扫描行、找线 | 基本不动 |
| `judge.py` | ~95 | 误差/状态判断、丢线、终点线 | 改逻辑才动 |
| `main.py` | ~75 | 开串口、开摄像头、死循环 | 基本不动 |

依赖关系是单向的，不会绕圈：

```
main.py  ──>  vision.py  ──>  config.py
   │                            ▲
   └────────>  judge.py  ───────┘
```

---

## 二、怎么让板子认识这四个文件（重要）

MaixPy IDE 点"运行"，只把**当前打开的那一个文件**发给板子。`import vision` 是去板子
的 flash 里找文件，所以**必须先存一次**，否则会报 `ImportError: no module named 'vision'`。

第一次使用，按这个顺序：

1. MaixPy IDE 连上板子（左下角出现 `>>>` 就说明连上了）
2. 在 IDE 里打开 `config.py` → 用工具栏的 **"保存文件到开发板"**
   （不同版本图标不一样，一般是向下的箭头；也可以 `文件 → 保存到开发板`）
3. 存的位置选 **`/flash`**（板子自带的 flash，不用 SD 卡）
4. 对 `vision.py`、`judge.py` 重复第 2~3 步
5. 打开 `main.py`，点**绿色三角运行**

之后：

* 只改 `config.py` 里的数字 → 要重新存一次 `config.py`，再运行 `main.py`
* 只改 `main.py` → 直接点运行，不用再存
* 板子断电重启后文件还在，不用重存

> 如果找不到"保存到开发板"按钮，还有个笨办法：把四个文件拷到 TF 卡根目录，
> 卡插进板子，开机后板子会自动运行 `/sd/main.py`。

## 三、接线

| K210（Maix Bit） | STM32F103 | 说明 |
|---|---|---|
| `IO24`（TX） | `PA10`（USART1_RX） | 数据从这边过去 |
| `GND` | `GND` | **必须接**，不接收到的全是乱码 |
| `IO25`（RX） | 不接 | STM32 那一头只开了接收，发不回来 |

供电各自独立，只要共地。

---

## 四、通信协议（和 `Protocol.c` 严格一致）

每帧 **4 个字节**：

```
0xAA | 误差(int8) | 状态(uint8) | 0x55
```

串口：`USART1`，`115200`，8 数据位 / 无校验 / 1 停止位，每秒约 25~30 帧。

### 误差（`g_target_error`）

车道中心相对画面正中间（第 80 列）偏了多少**像素**，范围 `-128 ~ 127`。

| 符号 | 含义 | STM32 会怎么动 |
|---|---|---|
| 正 | 车道中心在画面右边 = 车偏左 | `turn>0` → 左轮快 → 往右转 ✔ |
| 负 | 车道中心在画面左边 = 车偏右 | `turn<0` → 右轮快 → 往左转 ✔ |

和 `PID.h` 里"右偏为正"、`Service.c` 里 `target_left = base + turn` 是对上的。

### 状态（`g_car_state`）

| 值 | 什么情况 | `Service.c` 里的 base_speed |
|---|---|---|
| 0 | 直道 | 40 |
| 1 | 一般弯 / 远处看不见 / 长时间丢线 | 25 |
| 2 | 急弯，或确认要拐弯了 | 15 |
| 3 | 冲过终点线 | 停车 |

**丢线绝不会发 3。** 丢线 ≤10 帧照上次的结果继续发；超过 10 帧发状态 1 低速盲开。

## 五、上车前必须改的三个数

`config.py` 最上面：

```python
CAM_H_CM      = 20.0    # 镜头离地高度，厘米
CAM_PITCH_DEG = 30.0    # 镜头往下低头多少度
HFOV_DEG      = 90.0    # 镜头水平视场角
```

**扫描行选哪 5 行、每行"外侧黑线到车道中心差多少像素"，全靠这三个数现算**，不是写死的。

`HFOV_DEG = 90` 是按你给的 `1.8mm 焦距 + 1/4 英寸传感器` 算的
（`2·atan(3.6/2/1.8) ≈ 90°`）。高度和角度量到多少填多少，差两三厘米没关系 ——
跑起来会**自己量、自己修**。

改完先别上车，看启动时打印的表：

```
焦距 F=80.0 px   地平线在第 14 行   最近能看 0.09 m
  行  71  车前 0.26 m  间距  62 px  权重 3
  行  62  车前 0.33 m  间距  52 px  权重 3
  行  53  车前 0.43 m  间距  42 px  权重 2
  行  43  车前 0.62 m  间距  32 px  权重 2
  行  34  车前 0.94 m  间距  22 px  权重 1
```

**打印的距离跟实测差很多，就是高度/角度填错了。**

## 六、它是怎么找线的

每一行分三步：

1. **读整行**：把这一行 152 个像素全取出来
2. **这一行自己算黑白分界线**：`阈值 = 最暗 + (最亮 - 最暗) × 0.40`。
   每行各算各的，所以不怕灯光一边亮一边暗、也不怕自动曝光慢慢漂。
3. **找黑段**：
   * 两根线都在、间距对得上 → 取中点，最可靠
   * **只剩一根** → 判断它是外侧还是内圈，量到它再 ± 已知间距补出车道中心

第 3 步那个退路是必须的：顺时针跑时**外侧线永远在车左边、永远连续**，内圈线在过弯前
半米左右就会先拐走。只靠"两根取中点"会直接瞎掉。

跑起来后，凡是两根线都看到的行，会拿实测间距**慢慢修正那张间距表**（每帧改 1/16）。
高度量错 2cm 也会自己纠回来。

### 为什么要"提前打方向"

摄像头装 20cm 高、低头 30°，**离车 0.25m 以内的路面根本看不见**（这是镜头视场决定的，
换什么装法都一样）。所以每到弯口最后 0.2~0.3m，画面里只剩一根线甚至什么都没有。

对策：最近两行里**内圈线不见了、但按外侧线推出来车还是正对着的**，就判定"前面是右弯"，
把误差顶到 `CORNER_BIAS`（默认 40），状态降到 2。

前提是：**这条赛道顺时针跑，三个弯全是右弯**（90° / 38.5° / 103°）。
换逆时针或有左弯的赛道，把 `CORNER_BIAS` 改成 `-40` 或设 `0` 关掉。

## 七、调参顺序

1. **先只看画面**：`DEBUG_DRAW = True` 时，看 IDE 预览里 5 条横线上有没有画黑点。
   没有就调小 `CONTRAST_MIN`。
2. **对正中**：车摆正放车道中间，看打印的 `err`。**不是 0 就把这个数填进 `CALIB_OFFSET`**。
3. **静态试**：手拿着车左右平移，看 `err` 是不是"车往右移 → err 变负"。
   反了就改 `HMIRROR` 或 `VFLIP`。
4. **上车跑**：先调 STM32 那边的 `Kp`（从 0.05 试起），再加 `Kd`。
   `CURV_T1 / CURV_T2` 只影响降速时机，不影响方向。
5. 抖得厉害就把 `SMOOTH_SHIFT` 改成 1 或 2（越大越平滑、越迟钝）。

## 八、已知限制（别踩坑）

1. **77° 顶角最难**：转 103°、转弯半径只有 0.25m。车开到那儿会短暂看不见线，程序靠
   "记住最后的误差 + 状态 2 慢速"硬顶过去。**这个弯一定要慢慢过**，`CORNER_BIAS` 和
   STM32 的 `Kd` 要在这条弯上单独调。
2. **`HFOV_DEG` 有误差**会让扫描行偏。判断方法：车摆正，看 5 个 `间距` 值跟实测的黑线
   像素位置对不对得上，对不上就调 `HFOV_DEG`。
3. **`ROW_TWEAK`** 是应急旋钮：发现行选得太高（看太远）就设成 `+5`，太低就 `-5`。
4. **终点线检测默认关**（`FINISH_ENABLE = False`）。要开得先告诉我终点线长什么样，
   现在只认"整行变黑"这一种特征。
