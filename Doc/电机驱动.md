# 第 1 章 TB6612FNG 是什么

## 1.1 一句话

**一颗双通道 H 桥电机驱动芯片**，负责把 MCU 的弱信号（3.3 V、几 mA）变成能驱动电机的强信号（12.6 V、1 A 级别）。

## 1.2 为什么需要它

| 问题 | 说明 |
|---|---|
| **电压不够** | STM32 输出 3.3 V，电机要 12 V |
| **电流不够** | STM32 一个引脚最多 20 mA，电机堵转要 1 A+ |
| **不能换向** | GPIO 只能输出高低，不能反转极性 |
| **不能调速** | 需要 PWM 调制 |

## 1.3 引脚功能

| 引脚 | 功能 |
|---|---|
| VM | 电机电源（本项目 12.6 V，3S 锂电直通） |
| VCC | 逻辑电源（**必须 3.3 V**） |
| GND | 地 |
| AO1 / AO2 | 左电机输出（接电机红/黑粗线） |
| BO1 / BO2 | 右电机输出（接电机红/黑粗线） |
| PWMA | 左电机调速（PWM 输入） |
| AIN1 / AIN2 | 左电机方向 |
| PWMB | 右电机调速 |
| BIN1 / BIN2 | 右电机方向 |
| STBY | 待机（低 = 全部关闭） |

## 1.4 真值表（单通道）

| AIN1 | AIN2 | PWM | 电机状态 |
|---|---|---|---|
| 0 | 0 | 任意 | **停止（滑行，自由转动）** |
| 0 | 1 | PWM | **正转**，速度 ∝ PWM |
| 1 | 0 | PWM | **反转**，速度 ∝ PWM |
| 1 | 1 | 任意 | **制动（刹车，电机绕组短路）** |

本车只用了「正转」和「反转」，没有用「制动」——因为停车使用 `Motor_SetDuty(0,0)` → 滑行停车，不是急刹。

# 第 2 章 宏定义区

## 2.1 时钟（第 5~7 行）

```c
#define MOTOR_GPIO_CLK          (RCC_APB2Periph_GPIOA|RCC_APB2Periph_GPIOB)
#define MOTOR_TIM_CLK           RCC_APB2Periph_TIM1
#define MOTOR_TIM               TIM1
```

TIM1 是**高级定时器**（挂在 APB2 上，时钟 72 MHz）。

## 2.2 PWM 参数（第 9~13 行）

```c
// PWM参数：72MHz / (PSC+1) / (ARR+1) = 72M/1/3600 = 20kHz
// 分辨率 = 1/3600 ≈ 0.028%，比原来的 1/100 精细 36 倍
// 这样 MOTOR_DUTY_FULLSCALE=1000 的 ‰ 级指令才真正有意义
#define MOTOR_PWM_PSC           0
#define MOTOR_PWM_ARR           3599
```

计算：

```
72,000,000 / (0+1) / (3599+1)
= 72,000,000 / 1 / 3600
= 20,000 Hz
= 20 kHz
```

> **历史**：最初是 `PSC=35, ARR=99`（也是 20 kHz），但那时占空比只有 100 级分辨率。
> 现已改为 `PSC=0, ARR=3599`，频率不变、分辨率提高 36 倍。详见 [7.3 节](#73-已应用的改进原来只有-100-级分辨率)。

## 2.3 为什么是 20 kHz

| 频率 | 现象 |
|---|---|
| < 1 kHz | 电机发出「嗡嗡」的低频抖动，PID 会被干扰 |
| 1~8 kHz | **人耳最敏感区间，刺耳啸叫** |
| 8~16 kHz | 仍有高频噪音 |
| **20 kHz** | **刚好超过人耳上限**，完全听不到 ✅ |
| > 25 kHz | 开关损耗增加，TB6612 发热 |

**20 kHz 是「听不到」和「开关损耗可接受」的平衡点。**

## 2.4 占空比满量程（第 14 行）

```c
#define MOTOR_DUTY_FULLSCALE    1000
```

**语义：占空比指令单位是「‰」（千分之一）。**

- `1000` = 100 % 占空比
- `500` = 50 %
- `0` = 停

**为什么用 ‰ 而不是 %：**

PID 速度环输出是 `float`，直接输出 ‰ 有小数量级的分辨能力（虽然 `Motor_SetDuty` 接收 `int16_t`）。

更重要：**和 PID 的输出量纲完全一致**，中间零换算。这是好设计。

## 2.5 引脚分配（第 16~36 行）

| 功能 | 引脚 | 定时器通道 / GPIO |
|---|---|---|
| 左轮 PWM | **PA8** | TIM1_CH1 |
| 右轮 PWM | **PA11** | TIM1_CH4 |
| 左轮方向 AIN1 | **PB12** | GPIO |
| 左轮方向 AIN2 | **PB13** | GPIO |
| 右轮方向 BIN1 | **PB14** | GPIO |
| 右轮方向 BIN2 | **PB15** | GPIO |
| STBY | **PB5** | GPIO |

### 为什么左轮用 CH1、右轮用 CH4

| 通道 | 引脚 |
|---|---|
| CH1 | **PA8** ✅ |
| CH2 | PA9（被 USART1_TX 占了） |
| CH3 | PA10（被 USART1_RX 占了，接 K210） |
| CH4 | **PA11** ✅ |

**CH2/CH3 撞了 K210 的串口，所以只能跳着用 CH1 和 CH4。**

# 第 3 章 Motor_Init 逐段

## 3.1 GPIO 时钟（第 48 行）

```c
RCC_APB2PeriphClockCmd(MOTOR_GPIO_CLK, ENABLE);   // GPIOA | GPIOB
```

## 3.2 PWM 引脚配成复用推挽（第 50~53 行）

```c
GPIO_InitStruct.GPIO_Mode  = GPIO_Mode_AF_PP;     // 复用推挽
GPIO_InitStruct.GPIO_Pin   = MOTOR_LEFT_PWM_PIN | MOTOR_RIGHT_PWM_PIN;
GPIO_InitStruct.GPIO_Speed = GPIO_Speed_50MHz;
GPIO_Init(MOTOR_LEFT_PWM_PORT, &GPIO_InitStruct);
```

**`AF_PP`（复用推挽）** 是 PWM 输出的正确模式——引脚交给定时器外设控制，不由 GPIO 寄存器控制。

## 3.3 方向引脚：先写电平，再切模式（第 56~62 行）★

```c
/* 先在ODR写死电平再配成输出，避免切换瞬间出毛刺 */
GPIO_InitStruct.GPIO_Mode = GPIO_Mode_Out_PP;
GPIO_InitStruct.GPIO_Pin  = AIN1 | AIN2 | BIN1 | BIN2;

GPIO_SetBits(MOTOR_LEFT_DIR_PORT, AIN2 | BIN2);     // AIN2=1, BIN2=1
GPIO_ResetBits(MOTOR_LEFT_DIR_PORT, AIN1 | BIN1);   // AIN1=0, BIN1=0

GPIO_Init(MOTOR_LEFT_DIR_PORT, &GPIO_InitStruct);   // 最后才切成输出
```

**这是一个非常正确的顺序，很多人会写反。**

### 写反会怎样

```c
// ❌ 错误顺序
GPIO_Init(...);              // 先切输出，此时 ODR 是复位值 0
GPIO_SetBits(...AIN2...);    // 再写电平
```

**中间有一个极短的窗口，AIN1 = AIN2 = 0** → 真值表里这是「停止」，理论上没事。

但如果 ODR 恰好是 `AIN1=1, AIN2=1`（制动），而 PWM 已经在输出 → **瞬间制动一下，电机会「咯噔」抖一下**。

**先写 ODR 再切模式，保证切换瞬间电平就是想要的。**

## 3.4 STBY 先拉低（第 65~70 行）★

```c
/* STBY先拉低，待机，防止初始化期间电机抽动 */
GPIO_ResetBits(MOTOR_STBY_PORT, MOTOR_STBY_PIN);
GPIO_Init(MOTOR_STBY_PORT, &GPIO_InitStruct);
```

**目的**：初始化过程中所有引脚可能乱跳，先把驱动器关掉（STBY 低 = 输出高阻），**电机绝对不动**。

最后在所有配置完成后才拉高（第 105 行）。

**这是一个"安全初始化"的经典套路，值得学。**

## 3.5 定时器时基（第 73~80 行）

```c
TIM_TimeBaseInitStruct.TIM_Period    = MOTOR_PWM_ARR;   // ARR = 3599
TIM_TimeBaseInitStruct.TIM_Prescaler = MOTOR_PWM_PSC;   // PSC = 0
TIM_TimeBaseInitStruct.TIM_CounterMode = TIM_CounterMode_Up;
```

注释里写了 `//FIX 3：用宏，避免和换算常数脱节` —— 之前可能是直接写 `99`，改参数时容易和别处不一致。

## 3.6 TIM1 互补输出必须显式关闭（第 83~97 行）★★ 最重要的坑

```c
/* TIM1是高级定时器，N通道默认映射在PB13~PB15，必须显式清零
   防止互补输出抢走方向引脚 */
TIM_OCInitStruct.TIM_OutputNState = TIM_OutputNState_Disable;   // ★ 关键
```

### 这是什么问题

TIM1 是**高级定时器**，每个通道有两路输出：

| 通道 | 正常输出 | **互补输出（N）** |
|---|---|---|
| CH1 | PA8 | **PB13** |
| CH2 | PA9 | **PB14** |
| CH3 | PA10 | **PB15** |
| CH4 | PA11 | （CH4 无互补） |

**而本车的方向引脚正好是 PB12/PB13/PB14/PB15！**

**PB13/PB14/PB15 同时是「方向引脚」和「TIM1 互补输出」。**

如果互补输出被使能，定时器会**主动驱动**这三根线 → **方向控制完全失效**，电机行为完全不可预测。

### 怎么避免

```c
TIM_OCInitStruct.TIM_OutputNState = TIM_OutputNState_Disable;
```

`TIM_OC1Init` 内部会设置 `CCER` 的 `CC1NE` 位。设为 Disable → `CC1NE = 0` → 互补输出关闭 → PB13 保持 GPIO 功能。

### 补充：复位后本来就是 0

`CCER` 复位值 = 0，所以严格说即使不显式设也应该是关的。但：

- 代码显式设置 → **意图清晰，防止以后有人改错**
- 某些库版本或中断里可能动过 CCER

**这是防御性编程，好习惯。**

## 3.7 启动（第 100~101 行）

```c
TIM_Cmd(MOTOR_TIM, ENABLE);
TIM_CtrlPWMOutputs(MOTOR_TIM, ENABLE);      // ★ 高级定时器必须
```

### 为什么需要 `TIM_CtrlPWMOutputs`

**高级定时器（TIM1/TIM8）多一个 MOE（Main Output Enable）位。**

`TIM_Cmd` 只启动计数器，**不会让输出真正到达引脚**。必须再调 `TIM_CtrlPWMOutputs` 置 MOE。

**这是新手最常踩的坑之一**：CCR 设了、计数器转了，但引脚上什么都没有。

## 3.8 最后使能 STBY（第 105 行）

```c
/* 所有寄存器配置完毕，最后使能TB6612 */
GPIO_SetBits(MOTOR_STBY_PORT, MOTOR_STBY_PIN);
```

**顺序总结**：

```
① GPIO 时钟
② PWM 引脚 AF_PP
③ 方向引脚先写 ODR 再切输出
④ STBY 先拉低（驱动器关闭）
⑤ 定时器时基
⑥ 关闭互补输出
⑦ 启动计数器
⑧ 置 MOE
⑨ 最后拉高 STBY  ← 此时电机才真正启用
```

# 第 4 章 方向控制

```c
static void MotorLeft_SetDirection(uint8_t isForward)
{
    if(isForward == 1)
    {
        GPIO_ResetBits(AIN1);   // AIN1 = 0
        GPIO_SetBits(AIN2);     // AIN2 = 1
    }
    else
    {
        GPIO_SetBits(AIN1);     // AIN1 = 1
        GPIO_ResetBits(AIN2);   // AIN2 = 0
    }
}
```

对照真值表：

| isForward | AIN1 | AIN2 | 结果 |
|---|---|---|---|
| 1 | 0 | 1 | 正转 |
| 0 | 1 | 0 | 反转 |

**「正转」的定义取决于电机接线**：如果接线时红黑线接反了，这里的「正转」实际是反转。可以在软件里把 `actual` 取负，或直接对调电机两根线。

# 第 5 章 占空比换算

```c
static uint16_t Motor_DutyToCCR(int16_t duty)
{
    if(duty > MOTOR_DUTY_FULLSCALE)
    {
        duty = MOTOR_DUTY_FULLSCALE;      // 上限保护
    }
    return (uint16_t)((int32_t)duty * MOTOR_PWM_ARR / MOTOR_DUTY_FULLSCALE);
}
```

## 5.1 换算公式

```
CCR = duty × ARR / 1000
    = duty × 99 / 1000
```

| duty (‰) | CCR | 实际占空比 |
|---|---|---|
| 0 | 0 | 0 % |
| 100 | 9 | 9 % |
| 500 | 49 | 49 % |
| 1000 | 99 | 99 % |

## 5.2 为什么要乘 `int32_t`

```c
(int32_t)duty * MOTOR_PWM_ARR
```

`duty` 最大 1000，乘 99 = 99000，**超过了 `int16_t` 的 32767**。

如果不先转 `int32_t`，会发生溢出，结果完全错误。

**这类"中间结果溢出"是嵌入式最常见的隐蔽 bug 之一。**

## 5.3 为什么只保护了上限

函数只在 `duty > 1000` 时夹住，没有处理负数——因为调用方已经保证传入非负（`Motor_SetDuty` 里对负数取了 `-left_duty`）。

**这是一个"约定式"的隐式契约**，必须靠调用方遵守。

# 第 6 章 Motor_SetDuty

```c
void Motor_SetDuty(int16_t left_duty, int16_t right_duty)
{
    // 左轮
    if(left_duty >= 0)
    {
        MotorLeft_SetDirection(1);                       // 正转
        TIM_SetCompare1(MOTOR_TIM, Motor_DutyToCCR(left_duty));
    }
    else
    {
        MotorLeft_SetDirection(0);                       // 反转
        TIM_SetCompare1(MOTOR_TIM, Motor_DutyToCCR(-left_duty));   // 取绝对值
    }
    // 右轮同理，用 TIM_SetCompare4
}
```

## 6.1 设计要点

| 要点 | 说明 |
|---|---|
| **有符号入参** | 正 = 正转，负 = 反转，0 = 停 |
| **一个函数管两件事** | 方向 + 速度 |
| **取绝对值再换算** | `DutyToCCR` 只接收非负数 |
| **`duty == 0` 走正转分支** | 方向 = 正转，CCR = 0 → 实际停止（滑行） |

## 6.2 调用点（架构问题）

`Motor_SetDuty` 在整个工程里有 **4 个调用点**：

| 位置 | 用途 |
|---|---|
| `ServiceTask_5ms` | 正常控制输出 |
| `Task_CarStop` | 停车清零 |
| `Task_FetchVisionData` | 丢线急停 |
| `Task_CalculateTargetSpeed` | 终点停车 |

**4 个地方都能直接控制电机，一旦有 bug 很难排查。**

> 这是架构上的一个弱点：应该收敛成「只有一处能写电机」，其他地方只改状态变量。
> 但比赛前不建议重构。

## 6.3 没有做的事情

| 缺失 | 影响 |
|---|---|
| **死区补偿** | 低占空比时电机不转（静摩擦），PID 积分要慢慢爬上来 |
| **软启动（斜坡）** | duty 突变 → 电流冲击 → 电池电压瞬降 → 其他模块复位 |
| **堵转保护** | 电机卡死时电流过大，长期会烧 TB6612 |
| **电流限制** | 由 TB6612 自己限流（没有可编程限流） |

**前两项之前评估过，出于「赛前只做能编译+能上车验证的改动」的原则没有加。**

# 第 7 章 一个值得注意的分辨率问题

## 7.1 问题：实际 PWM 只有 100 级

```
ARR = 99  →  PWM 分辨率 = 1/100 = 1 %
```

而 PID 输出是 **0~1000（1000 级）**，映射到 CCR 只有 **0~99（100 级）**。

**结果是：10 个连续的 PID 输出值，映射到同一个 CCR。**

```
duty 500 → CCR = 49
duty 501 → CCR = 49
duty 502 → CCR = 49
...
duty 509 → CCR = 50
```

## 7.2 后果

| 场景 | 影响 |
|---|---|
| **中高占空比** | 影响小（1 % 相对误差） |
| **低占空比**（如 30 ‰ → CCR = 2） | **影响极大**，2 % 的分辨率意味着几乎无法微调 |
| **PID 细调** | 积分器辛苦积累半天，输出没有变化 → 表现为「响应迟钝」 |

```c
// 举例：duty 从 20 涨到 29，CCR 一直是 1
20 × 99 / 1000 = 1
29 × 99 / 1000 = 2   // 只有 29 才跳到 2
```

**低速时 PID 的精细调节被"量化"吃掉了。**

## 7.3 已应用的改进（原来只有 100 级分辨率）

**已于本次修改中应用。**

保持 20 kHz 不变，但提高计数分辨率：

```
PSC = 0,  ARR = 3599
→ 72,000,000 / 1 / 3600 = 20,000 Hz  ✅ 同样是 20 kHz
→ PWM 分辨率 = 1/3600 = 0.028 %      ✅ 提高 36 倍
```

改动内容（`Motor.c` 第 9~13 行）：

```c
// 改前
#define MOTOR_PWM_PSC           35
#define MOTOR_PWM_ARR           99

// 改后
#define MOTOR_PWM_PSC           0
#define MOTOR_PWM_ARR           3599
```

`Motor_DutyToCCR` 用的是 `MOTOR_PWM_ARR` 宏，**自动适配，不用改**：

```c
CCR = duty × 3599 / 1000      // duty=1000 → CCR=3599（满占空比）
```

**安全性**：TB6612FNG 数据手册标称开关频率可达 100 kHz，20 kHz 完全在范围内。**频率没变，只是每个周期内的计数更细**，对驱动器和电机没有任何额外压力。

**收益**：
- 低速控制更平滑（原来 30 ‰ → CCR=2，现在 30 ‰ → CCR=107）
- PID 的细调能真正生效，不再被量化吃掉
- 占空比指令的 ‰ 精度终于名副其实

**验证状态**：编译通过（0 错误 0 警告），**但未上车实测**。第一次上车时留意电机是否有异常噪音或抖动。

# 第 8 章 设计取舍与可改进点

## 8.1 做得好的地方

| # | 做法 | 价值 |
|---|---|---|
| 1 | **STBY 先拉低、最后拉高** | 初始化期间电机绝不抽动 |
| 2 | **方向引脚先写 ODR 再切模式** | 消除切换毛刺 |
| 3 | **显式关闭 TIM1 互补输出** | 避免 PB13~15 被抢占 |
| 4 | **`TIM_CtrlPWMOutputs`** | 高级定时器必须，否则无输出 |
| 5 | **输出直接是 ‰，与 PID 量纲一致** | 中间零换算，不易出错 |
| 6 | **`int32_t` 防中间溢出** | 隐蔽 bug 的预防 |
| 7 | **20 kHz 超出人耳** | 无啸叫 |

## 8.2 可以改进的地方

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | **PWM 只有 100 级** | 低速细调失效 | ARR 改 3599（见第 7 章） |
| 2 | **无死区补偿** | 低占空比不转 | 积分会自己处理，可不做 |
| 3 | **无软启动** | 电流冲击 | 赛前不做 |
| 4 | **4 个调用点** | 难排查 | 收敛成单点写入 |
| 5 | **无堵转保护** | 长期烧驱动器 | 加电流检测或超时 |
| 6 | **`Motor_DutyToCCR` 只保护上限** | 依赖调用方约定 | 加负值保护 |

# 第 9 章 常见故障排查

## 9.1 电机完全不转

| # | 检查 |
|---|---|
| 1 | **STBY 是否被拉高**（PB5）—— 拉低则全部关闭 |
| 2 | **VM 有 12.6 V 吗** |
| 3 | **VCC 是不是 3.3 V**（接 5 V 会导致高电平门限不匹配） |
| 4 | **`TIM_CtrlPWMOutputs` 调了吗**（高级定时器必需） |
| 5 | PWM 引脚是不是 `AF_PP` 模式 |
| 6 | 真值表：AIN1/AIN2 是不是都为 0（停止） |

## 9.2 只能单向转

| 原因 | 处理 |
|---|---|
| 某根方向线接错 | 对照真值表查 |
| 某根方向线虚焊 | 用万用表量通断 |
| 电机红黑线接反 | 对调两根 |

## 9.3 有啸叫

| 原因 | 处理 |
|---|---|
| PWM 频率在可听范围 | 确认 `MOTOR_PWM_PSC/ARR` 算出来是 20 kHz |
| 电机机械共振 | 换固定方式、加减震 |
| 电源纹波大 | 加大电容 |

## 9.4 低速不转，一给就猛冲

这是**死区 + 分辨率**的双重问题：

1. 电机静摩擦需要约 15~20 % 占空比才能启动
2. PWM 只有 100 级，低速时 1 级就是 1 %

| 解法 | 说明 |
|---|---|
| **靠积分慢慢爬** | PID 的 I 项会逐渐积累，最终突破死区（本车现状） |
| **提高 PWM 分辨率** | ARR 改 3599 |
| **死区补偿** | 输出 = 死区值 + PID 输出，但会造成小信号不连续 |

## 9.5 电机一转，单片机就复位

| 原因 | 处理 |
|---|---|
| **电源跌落** | 电机启动瞬间拉低电池电压，MCU 掉电复位 |
| 处理 | 加大电容（1000 µF 以上）、电机电源和 MCU 电源分开走线、加软启动 |
