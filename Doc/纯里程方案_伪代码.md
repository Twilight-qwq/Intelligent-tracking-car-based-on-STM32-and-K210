## 1. 一句话

**车按「走了多远」决定什么时候转，按「查表」决定转多少度；视觉只负责直道巡线，以及在明显不对时报警。**

## 2. 数据表（一圈 5 个弯）

| 相位 | 从哪出发 | 走多远 | 到哪个弯 | 转多少 |
|---|---|---|---|---|
| 0 | 起终点 | **147 cm** | 直角 | 90° |
| 1 | 直角 | **110 cm** | 钝角 | 39° |
| 2 | 钝角 | **200 cm** | 锐角 | 103° |
| 3 | 锐角 | **200 cm** | 钝角 | 39° |
| 4 | 钝角 | **110 cm** | 直角 | 90° |
| （回到 0） | 直角 | **147 cm** | 起终点 | — |

一圈总长 = 147+110+200+200+110+147 = **914 cm**。

## 4. 主循环（每 5 毫秒跑一次）

```
① 读左右轮编码器 → 得到两步走的计数

② 如果是「巡线」或「等里程」状态：
      走过的厘米 =（左计数 + 右计数）÷ 2 × CmPerCount
      Odo = Odo + 走过的厘米

③ 如果 Odo ≥ SegCm[Phase]：
      状态 = 转弯
      转角累计 = 0           ← 清零，开始数转弯的差速

④ 如果是「转弯」状态：
      左右轮按固定差速转：左 = 基速 + 差速，右 = 基速 − 差速
      转角累计 = 转角累计 +（左计数 − 右计数）

      如果 转角累计 ≥ TurnCnt[Phase]：      ← 转够了
          左右轮立刻恢复直行速度            ← 不能等下一帧视觉，会多转
          状态 = 恢复
          恢复计时 = 0
     否则如果 转弯超时（800 毫秒）：          ← 兜底，卡住了
          同上，强制结束

⑤ 如果是「恢复」状态：
      直行，最多 500 毫秒（让相机从弯道画面里缓过来）
      恢复计时到了 → 状态 = 巡线
      Phase = Phase + 1，如果 > 4 则回到 0     ← 换下一段
      Odo = 0

⑥ 如果是「巡线」状态：
      差速 = Kp × 偏差 + Kd × 偏差变化量
      左右轮 = 基速 ± 差速
```

**关键点：转弯的「停」由编码器说了算，不等视觉。** 视觉只在第 ⑥ 步参与。

## 5. 视觉怎么用（四条规则，双方已谈定）

| 情形 | 处理 |
|---|---|
| 里程还没到阈值，视觉报弯（差 > 30 cm） | **不转**。多半是反光。`Suspect = Suspect + 1` |
| 里程还没到阈值，视觉连续 3 帧报弯，且图案像真弯（最近 3 行全丢 + 只剩一条线），差 10~30 cm | **把 Odo 前移一半**（不是清零），然后继续等里程 |
| 里程到了阈值，视觉报不报 | **照转**，不看视觉 |
| 视觉长期不报弯 | **照转**，完全不等视觉 |

**核心原则：里程是硬信号，视觉是软信号。视觉只能用来「发现漂移」，不能改写里程基准。**

## 6. 错位怎么发现（这套方案唯一的自愈手段）

纯里程最大的风险不是精度，是**一旦错位自己不知道，后面全错**。所以必须有检测。

### 6.1 检测一：视觉报警计数

```
如果 Suspect ≥ 3（连续三个弯都出现「视觉先报、里程还差很远」）：
    说明里程系统性偏小（或者视觉系统性误报）
    动作：把 CmPerCount 上调 10%，Suspect 清零，并记一条日志
```

### 6.2 检测二：一圈对账

```
一个相位表走完（Phase 回到 0）时：
    这一圈总里程应该 ≈ 914 cm
    如果总里程 与 914 差超过 15%：
        说明里程刻度有问题，或者漏了一段
        动作：记日志 + 指示灯报警，但不停车
```

### 6.3 检测三（保底）：完全失联就退回老逻辑

```
如果连续两个相位都没被触发（里程一直不动，比如轮子打滑空转）：
    退回到「视觉报弯 → 转 90°」的老逻辑
    并且亮指示灯
```

**这条很重要**：新方案坏了也要能跑，不能比现在更差。

## 7. 现场标定（摄像头回来后 40 分钟）

### 7.1 校准里程刻度（10 分钟）

1. 在直道上用粉笔标一段 **294 cm**
2. 车从起点推到终点（不通电，纯推）
3. 读编码器累计的计数（标定台架模式已经做好了）
4. `CmPerCount = 294 ÷ 累计计数`
5. 和理论值 0.01402 比，差多少记下来

### 7.2 量三个弯的真实转角（30 分钟）

**方法**（每个弯做一次）：

1. 车贴着弯前的直道摆正
2. 地上沿车头方向画一条粉笔线（延长线）
3. 让车按差速转，转到车头大约对准出弯方向
4. **在车头位置点一个粉笔点**
5. 把车拿开，量「起点 → 粉笔点」的连线和原延长线之间的夹角
6. 这个角就是实际转角

**同时记下**：转过这个角，编码器累计了多少计数 → 这就是 `TurnCnt` 的标定值。

### 7.3 填表

把量出来的三个计数填进 `TurnCnt[5]`：
- 直角（90°）→ 现在 1730，量完再定
- 钝角（39°）→ 从没量过，必须新标
- 锐角（103°）→ 从没单独量过，必须新标

**不要按 1730 的比例外推**（打滑不是线性的，这条双方都强调过）。

## 8. 风险清单

| 风险 | 后果 | 缓解 |
|---|---|---|
| 起点没摆在起终点线上 | 全部错位 | 上电时按一下键「以此处为起点」，Phase 归零 |
| 里程读多（打滑） | 车转早 | 现场校准 CmPerCount；报警计数触发后自动上调 |
| 里程读少 | 车转晚 | 同上，反向 |
| 漏一次转弯 | 后面全错 | 一圈对账 + 视觉报警 |
| 三个角度量不准 | 每个弯都差 | 只能多次量取平均 |
| 打滑随地面变 | 换场地失效 | 每次铺完布重标一次（成本 2 分钟） |
