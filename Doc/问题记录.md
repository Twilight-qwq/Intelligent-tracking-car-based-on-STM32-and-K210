# 问题记录（从建车到现在，遇到过的所有坑）

> 用途：每一条都是**真的踩过**的，写明「现象 → 原因 → 怎么解决 → 教训」。
> 以后再遇到同样的现象，先在这里搜一遍，不要从零猜。
> 时间跨度：2026-11-16 ~ 2026-11-24。

---

## 一、视觉（K210 / 摄像头）

### 1. 直道画龙（车左右来回摆）

- **现象**：直道上车像画龙一样左右摆，越跑越收不住。
- **原因**：三个叠加 ——
  ① 视觉在弯口附近九行只剩 1~3 行，偏差本身在跳（单帧能跳 10~23 格）；
  ② 方向环 Kp 过大（0.231），偏差 13 格就要求 3 个计数差速；
  ③ 死区 ±3 格把「车头歪 2 度以内」的偏差整段吃掉，小偏差永远不纠。
- **解决**：Kp 0.231 → **0.15**；D 项每帧限幅 8 → **4**（挡住假跳变）；死区 3 → **1** 格。
- **教训**：**先治噪声，再谈加阻尼**。顺序反了会越调越糟。

### 2. Kd 一加大，画龙反而更严重

- **现象**：把 Kd 从 0.53 提到 1.10 想加阻尼，用户实测「更大了，十分严重的画龙」。
- **原因**：偏差会单帧跳 10~23 格（反光/褶皱骗的）。Kd 越大，跟着这些假跳变抽的鞭子越狠 ——
  那不是阻尼，是往火上浇油。
- **解决**：Kd 退回 0.53，改为把 **D 的每帧限幅从 8 砍到 4**。
  依据：真摆动时偏差每帧只变 3.4 格，限幅 4 对真阻尼毫无损失，却能把 10~23 格的假跳变砍掉大半。
- **教训**：**加阻尼之前必须先确认误差信号是干净的。**

### 3. 弯口的「假偏差」把车拽出去

- **现象**：一出弯车就被拽一下，看着像画龙。
- **原因**：只剩一条线时，中心是拿「车道半宽」倒推的（中心列 = 那条线 ± 半宽）。
  直道上倒推是对的，**弯里车道是拐的，同一条线倒推出来的中心能偏 ±30 刻度**。
- **解决**：**只有「两条线都在」的行，才准往偏差里投票**。单线行仍然参与判弯、判速度档。
- **教训**：推算值不能和实测值同权。

### 4. 九行的认线成功率差得很远（权重要按实测定，不能凭"越近越可信"）

- **实测**（最近 5 趟、1533 个采样块）：行 118(27.5cm) **54.0%**、行 103(34.6cm) **71.6%**、
  行 88(44.7cm) **67.8%**、行 71(63.3cm) 50.6%、行 64 64.1%、行 59 62.1%、行 56 45.6%、
  行 53 44.0%、行 51 47.0%。
- **发现**：**最近那行（27.5cm）反而是近四行里最差的**，而且宽块作废 26 次
  （它经常看到一大块黑 —— 车自己的影子/车头）。最靠谱的是 34.6 和 44.7 两行。
- **解决**：`NEAR_WEIGHT` 从 `(3,3,2,2)` 一路试到 **`(0,4,2,0)`**（完全不用最近那行）。
- **教训**：**权重应该按实测成功率定，不是按几何远近想当然。**

### 5. 「只剩外侧」很多，「只剩内侧」一次都没有

- **现象**：统计里 `只剩外侧`（只找到左边那条线）出现得很频繁，`只剩内侧` 是 0。
- **含义**：**内侧（右边）那条线经常丢**。而右转的弯里，内侧线丢了会直接把偏差带偏。
- **状态**：**未解决**。下次可以查：是不是右侧光照/阴影、或者扫描窗口把右侧切掉了。

### 6. 视觉零点不是 0（偏差在「车摆正」时读 −6 或 +2.5）

- **现象**：车摆在赛道正中，偏差却稳定读 −6（后又变成 +2.5），怎么调补偿都不彻底。
- **原因**：视觉零点（两条线中心的中点 vs 画面正中那一列）本身有偏移；相机装得略偏就会这样。
- **正确测法**：**车不动，把车依次摆最左 → 正中 → 最右，取左右两点的中点当零点**
  （左右两边各自的位置偏差方向相反，一平均就抵消）。
  **不要用「正中」那一点**：人眼判断 40 厘米宽车道的中心，偏 5~7 厘米很正常。
- **实测**：最左 +25、正中 +15、最右 −20 → 零点 = (+25−20)/2 = **+2.5 格（≈1.2 厘米）**。
- **解决**：`LINE_ERR_OFFSET = −2.5`（只负责把零点对齐到 0）。
- **教训**：**换个视觉权重、动过相机角度，零点必须重新量，不能沿用。**

### 7. K210 跑两秒突然停（UnboundLocalError）

- **现象**：车跑两秒突然停，日志里偏差冻结、目标速度归 0。
- **原因**：给「看不全就沿用上次偏差」加计数器时，函数里写了 `hold_frame_count += 1`
  却没加 `global hold_frame_count` → 局部变量未赋值就自增 → 抛异常 → 脚本崩。
- **解决**：函数开头补上 global 声明。
- **教训**：MicroPython 里在函数内给模块级变量赋值，**必须写 global**。

### 8. 「看不全就沿用上次偏差」在弯口反而害人

- **现象**：加了「丢线时沿用上次偏差」，直道好了，但弯口出错（车被一个旧的大偏差一直拽着）。
- **原因**：弯口九行大面积掉，上一次有效的偏差很可能正是弯道的假偏差；无条件沿用 = 一直按它打方向。
- **解决**：加三个条件 —— ① 上次偏差本身很小（|偏差| ≤ 6 格，说明在直道）
  ② 最多连续沿用 3 帧 ③ 一出现有票的帧就清零。任何一条不满足就置 0。
- **教训**：**"沿用旧值"这种保护，必须限定在"旧值可信"的条件下。**

### 9. 起点没摆正，被误判成「视觉坏了」

- **现象**：日志里九行全是 `没线 宽块1`（一条 92 像素宽的黑块），看着像摄像头坏了。
- **原因**：**车根本没在纸上**，在赛道外面起步。
- **解决**：每次跑前把车摆到起点线正中。
- **教训**：看到"九行全灭"，先确认车在不在赛道上，再怀疑硬件。

## 二、控制（STM32）

### 10. 转弯被编码器兜底掐断，只转了 43°

- **现象**：车先左摆头（转弯已开始），然后只摆了一半就直着冲墙。
- **原因**：`TURN_COUNT_BACKSTOP` 按理论计数设（1487 × 1.05 ≈ 1561），
  但**原地打转时轮胎打滑，编码器数出的角约是真值的 2 倍** → 兜底抢在陀螺仪前面把转弯掐断。
- **解决**：兜底比例 1.05 → **3.0**（只防"陀螺仪冻住"这一种情况），超时 800 → 600 毫秒。
- **教训**：**打滑时编码器不可信，角度必须听陀螺仪的。**

### 11. 转弯有时候 90°、有时候 180°（真 bug，已修）

- **现象**：同一个弯，有时候正常 90°，有时候转 180°（车头对着墙）。180 正好等于超时。
- **原因**：`Gyro_Update()` 里 **`Gyro_LastUpdateMs = current_ms;` 写在「读数据之前」** ——
  读失败的那一拍，时间戳已经被更新，那一拍的转动**永久丢失**。
  陀螺仪积分是「转速 × 时间」，时间被吃掉角度就少算 → 程序以为没转够 → 拖到 600 毫秒超时 → 180°。
  而转弯时电机振动和大电流干扰最重，I2C 读失败的次数每次都不一样 → **忽好忽坏**。
- **解决**：时间戳挪到「读成功之后」才更新，丢的那段下一次成功时一次性补回来（单次最多补 50 毫秒）。
- **教训**：**积分器的 dt 必须只在"样本有效"时才推进。** 这类错误不会一次就露出来，只在 I/O 抖动时才发作。

### 12. 陀螺仪偶发 −999（软件 I2C 太快）

- **现象**：整趟没有陀螺仪，遥测 I3 发 −999。
- **原因**：软件 I2C 位延时只有 25 次空转 ≈ 500 kHz，而总线是开漏、靠模块自带的上拉 → 太快，读不稳。
- **解决**：位延时 25 → **100 次空转（约 125 kHz）**；开机重试 5 → **20 次**；
  停车时每秒再试一次救回（`Gyro_TryRecover`）。
- **根治（未做）**：加 4.7 kΩ 上拉电阻、I2C 线远离电机线、电机端子加 0.1 µF 电容。

### 13. 转弯多转的那部分全是惯性，而且忽多忽少

- **现象**：同一个弯，落地角度每次差 ±8 度。
- **原因**：陀螺仪到了目标角只是撤掉**命令**，车身还在以约 200 度/秒转，靠地面摩擦慢慢停，
  这一段程序完全不管。滑多少取决于电池电压、地面摩擦、打滑程度。
  角度表里那个 ×0.87 是**按平均值**补的固定数，补不了波动。
- **试过但失败的两条路**：
  - **降差速**（11.55 → 9.0）：右轮目标只剩 6 个计数，克服不了静摩擦被拖停，
    车身变成绕右轮硬拧，转速不可控 → 实测稳定转 **180°**。**此路不通。**
  - **按转速预测提前停**（`|角度| + |转速| × 0.1 ≥ 目标` 就停）：实测"大概率转 180°"，
    原因未确证（怀疑转速估计头几拍不准，提前量乱跳）。**已整体撤回。**
- **当前值**：角度表 `{78, 20.5, 90, 28.5, 78}`（手调实测）、差速 11.55、超时 600 毫秒。
- **教训**：这套数是**用眼睛一趟一趟标出来的**，任何"理论上更优雅"的改法都会把这套标定推翻，
  代价是重新标五个弯。**不要轻易改。**

### 14. 惯性的代价上限（保险）

- **做法**：加「陀螺仪冻住检测」——转弯中若「编码器已数了 1400 计数（车确实在转）」
  且「陀螺仪角度还 < 10 度」，判定哑火，立刻结束转弯。
- **效果**：陀螺仪哑火时停在约 80~90°（可救），而不是 180°（灾难）。

### 15. 死区太大，直道上慢慢往内线靠

- **现象**：直道上车一直往内线贴，怎么调零点补偿都不彻底。
- **原因**：死区 ±3 格 = 1.44 厘米。但偏差是在车前 **40 厘米**处量的，
  换算成车头角度：**车头歪 2 度 → 40 厘米外偏 1.4 厘米 ≈ 3 格 → 被死区吃掉**。
  也就是「车头歪 2 度以内，方向环这辈子都不纠」。车按 56 厘米/秒 斜着爬，95 厘米能爬 20 厘米。
- **解决**：死区 3 → **1 格**（0.48 厘米 ≈ 车头 0.7 度）。
- **教训**：**死区要用"角度"去换算，不能只看像素数。**

### 16. 出弯后「左摆头」（车真的又往左转了 94°）

- **现象**：转完弯车头往左一甩。
- **原因**：出弯后视觉冻在 −20 长达 **1.2 秒**（12 帧一模一样），方向环照着这个 −20 一直往左打死；
  陀螺仪证据：这 1.2 秒里从 −97.6° 退回 −3.6°，**车真的往左转了 94°**。
- **教训**：**方向环不能相信"冻住的"偏差。** 视觉那边"沿用上次"的保护要有限度。

### 17. 改阈值对钝角弯"完全没反应"

- **现象**：第 2 个弯的阈值试了 110 / 95 / 88，车的开转位置一动不动。
- **原因**：那时开转走的是「视觉报弯 + 16 厘米」那条路（`TURN_ARM_CM`），跟阈值无关。
- **解决**：把 `TURN_ARM_CM` 改成 999（彻底关掉那条路），**开转点只由阈值决定**，
  一个弯只剩一个旋钮，而且它是线性的（阈值减 5 = 提前 5 厘米）。
- **教训**：**改一个参数没反应，先确认它是不是被另一条路接管了。**

### 18. 里程强转被视觉状态挡住（`Corner_Done` 锁存）

- **现象**：钝角弯既不按里程转，也改不动。
- **原因**：「这一弯转过没有」原来用 `Corner_Done` 表示，而它的生死由**视觉**决定
  （要视觉说"这里不是弯了"才清）。它一旦卡在 1，里程强转整条路就被挡在门外。
- **解决**：改成 `Corner_TurnedForIndex`，**只跟弯序号走**：开转置 1、弯序号前进清 0，跟视觉无关。
- **教训**：**里程类的判据不要依赖视觉状态。**

### 19. 到终点不停车，还反复右拐 90°

- **现象**：转完最后一个直角弯后直走一段没停，反而又右拐 90° 继续开。
- **原因**：结构性死循环 ——
  `FINISH_STOP_CM = 99`（要数 99 厘米才停），但最后一个弯的阈值是 75，
  强转点 = 75 − 10.7 = **64.3 厘米**。64.3 < 99，于是**还没数到 99 就先转了一次**，
  转弯一结束段内里程又清零 → 永远到不了 99 厘米 → 每 64 厘米右拐一次，永不停车。
- **解决**：给里程强转和视觉报弯都加 `Finish_Armed == 0` 的条件 —— **转完最后一个弯就不许再转**。
- **教训**：**"停车里程"必须大于"最后一个弯的开转里程"**，否则逻辑上就死循环。

### 20. 编码器坏了，里程全错 → 转弯永远"晚"

- **现象**：转弯位置忽然全都不对，以为要重新标定阈值。
- **原因**：左编码器没信号（见第 22 条）。里程是拿两个编码器算的，坏一个里程就偏小 → 车永远"没走到"。
- **教训**：**遇到「转弯位置突然不对」，先看 I1/I3 两个轮子的实际速度，别先怀疑控制参数。**

## 三、机械 / 电气

### 21. TB6612 烧毁

- **现象**：一趟跑下来车一步不动，目标速度一直 20、两个轮子实际一直是 0。
- **原因**：堵转时 12.6 V 直接加在电机绕组上 → 6~12 A，而 TB6612 绝对最大只有 3.2 A（峰值）/1.2 A（连续）。
  （顺便澄清：**停车"抱死"不是凶手** —— 一次抱死能量只有 0.1 焦耳量级，温升几度。）
- **解决**：加堵转保护 `Task_5ms_StallGuard()`：目标 ≥15、两个速度环正向顶到 999‰、
  实际速度 < 1.5 计数、连续 400 毫秒 → 断输出+停车。启动后 500 毫秒宽限。
- **教训**：电机堵转的电流是驱动芯片额定值的 5~10 倍，必须有软件保护。

### 22. 左编码器 GND 被接到 5V → 左轮全速疯转，车自己画弧

- **现象**：车自己拐弯/画弧，一边轮子明显比另一边快；VOFA 里 I1（左轮实际速度）手转电机一直是 0。
- **原因**：**左编码器的 GND 接到了 5V**（整排插错一位）。编码器等于没有供电 → 不出数 →
  速度环以为轮子没转 → 占空比顶到 100% → 左轮全速。
- **排查办法（顺序）**：
  ① 交换法：把左右电机的插头整体对调，看现象跟不跟着电机走（跟走 = 电机/编码器；不跟 = 主板）
  ② 万用表：编码器 VCC-GND 有没有 3.3/5 V；手转轮子时 A 相对 GND 有没有 0↔VCC 跳变
  ③ 量主板那一端的引脚
  ④ 交换法只对调编码器信号线（不动电机动力线），能分开"编码器坏"和"主板坏"
- **烧毁风险**：GND 被抬到 5V 时，编码器只是"没电"，一般不会烧；
  但如果 VCC 是 3.3V 而 GND 是 5V，那就是反接 −1.7V，有风险。
  另外它的输出相对板子地会抬高 5V —— STM32 的 **PA15/PB3 是 5V 容忍脚（FT）**，5V 扛得住，超过 5.5V 才危险。
- **教训**：**插头"整排错一位"是最常见的接错形态**，要逐根核对 VCC/GND/A/B，别只看一根。

### 23. 左编码器 P3 引脚的特殊要求

- 左编码器用 TIM2 部分重映射：CH1=**PA15**、CH2=**PB3**。这两个脚复位后是 JTAG 的 JTDI/JTDO。
- 代码里靠 `GPIO_Remap_SWJ_JTAGDisable` 关掉 JTAG 才能用。
- **硬件上 PB3 必须串 1 kΩ 电阻**，否则插着下载器复位时会和 JTDO 对顶。
- **教训**：用 JTAG 复用脚做编码器输入，一定要在原理图上标注这个电阻。

### 24. 原地打转时轮胎打滑，编码器读数约为真实值的 2 倍

- **实测**：编码器认为转了 82°，陀螺仪只认 43°。
- **影响**：所有按编码器计数设的转弯判据都会**提前**。
- **解决**：转弯角度一律听陀螺仪的，编码器只作为"陀螺仪冻住"时的兜底。
- **教训**：**轮子转 ≠ 车身转。**

### 25. 陀螺仪模块偶尔整趟不认

- **现象**：开机 WHO_AM_I 一次没读通，整趟没有陀螺仪。
- **解决**：开机重试 20 次；停车时每秒再试一次 `Gyro_TryRecover()`。
- **状态**：仍是"时好时坏"的硬件。根治要动线。

## 四、流程 / 工具

### 26. 跑车的时候一根 USB 线都不许插

- **原因**：K210 和 STM32 的 USB 线同时是「供电 + 通信」。插着线跑车，线就把车和电脑拴在一起，
  车往前跑 1 米电脑就得跟着挪 1 米 —— 赛道上没人给你拽电脑。
- **正确的数据获取方式**：
  - K210 那一侧：**靠 SD 卡**。脚本里有 `RECORD_TO_FILE = True`，每帧写进 `run_log.txt`，
    跑完把卡拔出来在电脑上看。
  - STM32 那一侧：**遥测是蓝牙的**（见下一条），本来就无线。
- **教训**：任何"看数据"的方案，先问一句：**要不要插着线跑车？** 要插 → 直接否掉。

### 27. COM3 / COM4 / COM5 / COM15 全是蓝牙串口

- **发现**：注册表里 `\Device\BthModem0~3` 分别对应 COM15 / COM3 / COM4 / COM5。
- **含义**：**STM32 的遥测一直是走蓝牙的，本来就无线。** 之前误以为是 USB 线，白折腾了很久。
- **用法**：车上电、手机端 VOFA+ 断开，电脑上就能抓，不用插任何线。

### 28. `mid_delay.c` 被别的 AI 删掉，编译报找不到文件

- **现象**：`cannot open source input file "MID\Src\mid_delay.c"`。
- **原因**：`bsp_gyro.c` 还在调 `Delay_ms()`（陀螺仪上电等待/重试/启动等待），工程里也还登记着它。
- **解决**：按 git 里的原样恢复，内容一字未改。
- **教训**：**删文件之前先搜谁在用它。**

### 29. `run_log.txt` 取不出来

- **现象**：K210 插上电脑后，SD 卡**不挂成盘符**；发 Ctrl+C 也停不了脚本（主循环被 try 包住/REPL 不收输入）。
- **解决**：只能把 TF 卡拔出来插读卡器。
- **教训**：**改视觉脚本必须依赖读卡器**，跑车现场要带。

### 30. 抓包前必须先断开 VOFA+ / MaixPy IDE

- **现象**：报「对端口 COMx 的访问被拒绝」。
- **原因**：同一个串口只能一个人开。

## 五、通用教训（压成十句话）

1. **先确认「我拧的是不是那个旋钮」** —— 改参数没反应，多半是被另一条路接管了。
2. **先治噪声，再谈加阻尼** —— 顺序反了会越调越糟。
3. **积分器的 dt 只在样本有效时才推进** —— 否则 I/O 一抖就丢角度。
4. **死区要用角度换算**，不能只看像素数。
5. **轮子转 ≠ 车身转** —— 打滑时编码器不可信。
6. **里程判据不要依赖视觉状态。**
7. **"沿用旧值"必须限定在"旧值可信"的条件下。**
8. **看到"九行全灭"先确认车在不在赛道上**，再怀疑硬件。
9. **任何"看数据"的方案，先问要不要插线跑车。**
10. **只有实车能测的数，直接听实测加减，别自己插值/推算。**

## 六、参数演进史（2026-11-24 从代码注释里搬过来的）

> 代码里的注释已经精简成「这个数是什么」，**为什么变成现在这个值**全部移到这张表。
> 改参数前先看这里，别把踩过的坑再踩一遍。

### 6.1 五个弯的阈值（`Turn_ThresholdCm`，厘米）

| 弯 | 图纸值 | 演进过程 | 现在 |
|---|---|---|---|
| 1 号（直角 90°） | 180 | 200 → 197 → 189 → 184 → **188** | 188 |
| 2 号（钝角 38.5°） | 110 | 95 → 85 → 70 → **77** | 77 |
| 3 号（锐角 103°） | 240 | 190 → **185** | 185 |
| 4 号（钝角 38.5°） | 240 | 190 → **185** | 185 |
| 5 号（直角 90°） | 110 | 75 → **79** | 79 |

- **图纸值普遍偏大**，全部要实测标定。
- 标定方法：跑一趟，用眼睛报「早一拃（20 厘米）/ 早半拃 / 正好 / 晚一点点」，一次改 5~10 厘米。
- **教训**：不要用两点插值去猜。曾经按「180 时早 20、200 时晚 3」插出 197，实测用户说"还是晚了"，要减 8 才好。

### 6.2 五个弯的角度（`Turn_AngleDeg`，度）

| 弯 | 真实角度 | 演进过程 | 现在 |
|---|---|---|---|
| 1 号 | 90 | ×0.87 得 78 → 76 | 76 |
| 2 号 | 38.5 | ×0.87 得 33.5 → 28.5 → 20.5 | 20.5 |
| 3 号 | 103 | ×0.87 得 90 | 90 |
| 4 号 | 38.5 | ×0.87 得 33.5 → 28.5 | 28.5 |
| 5 号 | 90 | ×0.87 得 78 → 75 | 75 |

- 那个 **×0.87** 是补惯性过冲的固定系数（命令少给 13%，靠惯性滑到位）。
- 后来改成真实角度 + 「按转速预测提前停」，**实测"大概率转 180°"，已整体撤回**。
- **教训**：这套数是眼睛一趟一趟标出来的，任何"理论上更优雅"的改法都会把这套标定推翻，代价是重标五个弯。

### 6.3 转弯动作

| 参数 | 演进 | 现在 | 说明 |
|---|---|---|---|
| `TURN_VALUE`（差速） | 11.55 → 9.0（**失败，撤回**） | 11.55 | 降到 9.0 时右轮目标只剩 6 个计数，克服不了静摩擦被拖停，车身绕右轮硬拧 → 稳定转 180° |
| `TURN_TIMEOUT_MS` | 800 → 600 → 900（试降差速时）→ 600 | 600 | 兜底最后一道闸；陀螺仪哑火时就是这个在停 |
| `TURN_COUNT_BACKSTOP_RATIO` | 1.05 → **3.0** | 3.0 | 1.05 会抢在陀螺仪前面把转弯掐断（只转了 43°）；打滑时编码器读数是真值约 2 倍 |
| `TURN_ARM_CM` | 20 → 16 → **999** | 999 | 999 = 关掉「视觉报弯 + 走 N 厘米」那条路，开转点只由阈值决定 |
| `TURN_ARM_TURN_MAX` | 3.0 → **1.2** | 1.2 | 3.0 时弯前 16 厘米最多能拧 28°，太多；1.2 只拧 11° |
| `TURN_STRAIGHT_DIFF_MAX` | **新增 1.5** | 1.5 | 直道差速硬上限 ≈ 32 度/秒，防"远端提前看到下一个弯"把车一路往内线带 |

### 6.4 方向环（外环）

| 参数 | 演进 | 现在 | 说明 |
|---|---|---|---|
| `Kp` | 0.5（画龙）/ 0.1（太钝）/ 0.231 → 0.18 → **0.15** | 0.15 | 0.231 时直道左右各摆 ±9 度收不住 |
| `Kd` | 0.53 → 1.10（**更严重，撤回**） | 0.53 | 偏差会单帧跳 10~23 格，Kd 越大跟着假跳变抽得越狠 |
| `LIMIT_LINE_DIFF_MAX` | 8 → **4** | 4 | 真摆动每帧只变 3.4 格，限幅 4 不吃亏；能把假跳变砍掉大半 |
| `LINE_ERR_DEADBAND` | 3 → **1** | 1 | 3 格 = 1.44 厘米，但换算成车头角度是 **2 度**：歪 2 度以内永远不纠 |
| `LINE_ERR_OFFSET` | 0 → 6 → 3 → −1.5 → −5.5 → **−2.5** | −2.5 | 只负责对齐视觉零点（实测零点 +2.5）。用它治"路段漂移"必然顾此失彼 |
| `LINE_KI` | 新增 0.6 → **0（停用）** | 0 | 积分对常值偏置是放大器，而这里的偏置来自"读数本身"，越积越糟 |
| 死区语义 | 补偿 0 时压外侧线、补偿 6 时贴内侧线 | — | 残差 = 零点 + 补偿；残差为 0 表示车跑在中线 |

### 6.5 路段偏置（`Turn_LineBias`，仅两个钝角弯）

| 参数 | 演进 | 现在 |
|---|---|---|
| `TURN_BIAS_WINDOW_CM` | 60 → **80** | 80 |
| `Turn_LineBias` | 新增 −12 → **−26**（只填第 2、4 个弯） | `{0, −26, 0, −26, 0}` |

- 来由：钝角弯那一段**线的中线本身就往右拐**，车跟着右移是几何必然，**只发生在那一小段**。
- 用全局固定补偿去治它必然顾此失彼（0 / 1.5 / 3 / 6 / −5.5 全试过，就是那时候来回折腾的）。
- **教训**：只有"局部现象"用"局部参数"治才对。

### 6.6 视觉（`VisualTest\live_scan_test.py`）
