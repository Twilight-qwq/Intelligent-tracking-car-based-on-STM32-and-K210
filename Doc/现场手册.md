### 1.2 两根线怎么接（接错就完全没反应）
| 陀螺仪（软件 I2C） | 主控 | 语音模块（USART3） | 主控 |
|---|---|---|---|
| VCC / GND | 3.3V / GND | 模块 TX | **PB11** |
| **SCL / SPC** | **PB0** | 模块 RX | **PB10** |
| **SDA / SDI** | **PB1** | GND | 共地 |
| **SAO / SDO** | **GND**（地址 = 0x68） | — | — |
| CS / INT / FSY | 悬空（= I2C 模式）/ 不接 | — | — |

→ 接完核对：语音**线是交叉的**（模块 TX 进 PB11）。接成直的 = 完全没反应。

## 2 上电与开机顺序

**按这 7 步，顺序不许换：**

1. **拔掉所有 USB 线**（K210 的、STM32 的）→ 确认一根不剩 → 才做下一步。
2. **车摆到起点线正中**（必须摆正）→ 摆歪了日志里九行全是 `x`，会被当成"视觉坏了"。
3. **开电池开关** → 看灯：**快闪** = 视觉还没起来；**慢闪** = 可以按启动了。
4. **等它慢闪** → 没慢闪别按启动键（会撞）。
5. **按一下启动键，松手**（按一次翻转一次；不用按住，不用跟着车走）。按键找不到 → 手机蓝牙发「启动」，或喊语音「启动」（帧 `AA 01 55`，波特率 **9600**）。
6. **车自己跑完自己停** → 跑的时候人跟着看，不许碰车、不许插线。
7. **跑完以后才插线**：K210 插回电脑 → 卡挂成 `G:` → 读 `G:\run_log.txt`。挂不上就拔卡插读卡器。

**开机那 2 秒在定曝光** —— 所以第 2 步必须排在第 3 步前面：**先摆车，再上电**。
**启动门禁**：视觉没起来（`Vision_EverSeen` 为假）→ 按按键、说启动**都被忽略**，灯还是快闪（免得"说了启动、人走开、车突然窜出去"）。**停车不需要门禁**：任何条件下发 `AA 02 55` 都停；要立刻停 → 再说一次「停车」，或再按一次启动键。
**陀螺仪保险**：模块不在/读不到 → `Gyro_Ok=0`，后面全跳过，**不影响现在跑车**。

**台架模式（只在架空空转时用，车不许下地）**：上电时**长按按键** → 手机 VOFA+ 看五个通道：ch1 = `WHO_AM_I` 应为 **18**（或 104）／ch2 = Z 轴原始读数（静止时固定值附近小幅抖）／ch3 = 累计角度（**手转 90° 走到 ±90 左右**）／ch4 = 零偏（上电 1 秒后自动算出）／ch5 = 读失败次数（一直 0）。
→ ch1 不是 18 就停下查接线（§1.2）；ch1 = 18 再往下走。

## 3 三层改参数

**原则：先试最快的；每次只改一个；改完跑一次看效果。**

### 3.1 第一层：蓝牙改，**10 秒，不用编译不用拔卡**
指令格式：`AA | 指令码 | 浮点4字节(小端) | 55`

| 现象 | 指令 | 从 → 到 |
|---|---|---|
| 直道画龙（摆得厉害） | `0x05` Kp | 0.231 → **0.15** |
| 直道太迟钝、回正慢 | `0x05` Kp | 0.231 → **0.30** |
| 摆动衰减太慢 | `0x06` Kd | 0.53 → **0.90** |
| Kd 加大后开始抖 | `0x06` Kd | 调回 **0.53** |
| 整体太快、来不及反应 | `0x07/0x08/0x09` | 30/25/15 → **25/20/12** |

举例（Kp 改成 0.15）：`AA 05 9A 99 19 3E 55`

> 这是【11-21】原表，起点写 0.231。**11-24 现值已是 Kp 0.15 / Kd 0.53**，改前先看代码里的现值，别照 0.231 算。
> **蓝牙改的值掉电就回到代码里的值，不是永久的。**

### 3.2 第二层：改卡上参数，**5 分钟（拔卡 + 记事本 + 插回）**

| 现象 | 参数 | 从 → 到 | 为什么 |

## 4 实车测试三阶段（必须按顺序，不许跳）

### 4.1 开跑前必改两个数（不改就是白跑）
| 位置 | 现在 | 实车要改成 | 不改的后果 |
|---|---|---|---|
| `SM_FUSE_M` | **99**（手推专用，等于关掉） | **2.5** | 判错弯时车永远卡在最慢档，出不来 |
| `SEND_UART` | **False** | **True** | 车根本不动（视觉发了也没人收） |

→ 两个都改完 → 存盘插回 → 才做阶段一。

### 4.2 阶段一：架空试转向（最安全，先做这个）
1. 把车**架空，四个轮子离地** → 才上电。
2. 用手把车头**往右**摆一点 → 看轮子：**左轮应该比右轮慢**（车要往左拐回来）。
3. 反过来往左摆一次 → 看右轮比左轮慢。
4. **方向反了就别往下走，立刻断电停下。** 方向反了实车必然撞。

### 4.3 阶段二：直道低速
1. 车放直道中间，**20 档**（先别上 30 档）→ 按启动。
2. 让它自己跑一段直道 → 看两件事：**能不能沿直线**、**偏差会不会越跑越大**。
3. 跑完拔卡看 `run_log.txt`。

### 4.4 阶段三：单个弯
1. 从弯前直道开始，**还是 20 档** → 看它能不能转过去。
2. 看日志里三件事：① 降档有没有在弯前完成 ② 方向接管有没有触发 ③ **出弯后好行恢复得有多快**。

### 4.5 调 Kp（只有这一种加法）
`0x05` 设 Kp、`0x06` 设 Kd，从 **0.175** 起步，一次加一点 → **每次改完都回去跑阶段二那段直道**，看偏差收敛速度。

- 起点为什么 0.175：基速 30 时余量 37 − 30 = **7 counts**，7 ÷ 40 = **0.175**；合理区间 **0.09 ~ 0.175**。
- 基速降到 25：余量 12 → Kp 起点 **0.30**。
- 方向环是 **PD**（Kp + Kd，没有 Ki）；判据看**收敛还是发散**，没有"稳态误差"这回事。

## 5 现场应急补救（光照变了 / 赛道尺寸不一样 / 跑歪了）

### 5.1 光照变了（认不出线、好行很低）
1. 先跑一遍看 `好行`：**长期 < 4** → 往下走。
2. 改卡上 `LOCK_EXPOSURE`：`True` → **`False`**（回自动曝光）→ 重新上电 → 再看好行。
3. 还不够 → 改分界线比例 **0.55**（式子：`最暗 + (最亮−最暗) × 0.55`）；**不许超过 0.65**（超了地面会变黑）。
4. 对比度下限 **70**：现场实测都在 70~110 就够用；不到 70 是场地太暗，不是参数问题。

### 5.2 赛道尺寸不一样
| 情况 | 怎么判断 | 怎么办 |
|---|---|---|
| **车道宽度不同** | 采样块每行后面有 `实 XX 理 YY`，两个数差得多 | 把 `ROW_HALF_LANE_WIDTH_PX` 按比例改：`理 × (实 ÷ 理)` |
| **线太粗/太细** | `好行` 一直很低，但采样块显示线其实认得出来 | 调 `ROW_MIN_RUN_PX` / `ROW_MAX_RUN_PX`（线宽上下限） |
| **整体都不对** | 好行长期 < 4 | 先试 §5.1 第 2 步（关锁曝光），再考虑重标每行半宽 |

> **里程刻度不要在现场校**：`CM_PER_COUNT` 保持理论值 **0.01402**，手推标定已永久取消（见 §9）。刻度错 5% 只会让转弯点前后挪几厘米，不会指错弯。

### 5.3 跑歪了（画龙 / 回正慢 / 抖 / 单向偏）
1. **画龙**（摆得厉害）→ 蓝牙 `0x05` 把 Kp 往小：11-24 现值 0.15，11-21 那次是 0.231 → 0.15。
2. **回正慢**（太迟钝）→ 蓝牙 `0x05` Kp → **0.30**。
3. **摆动衰减太慢** → 蓝牙 `0x06` Kd 0.53 → **0.90**；**加大后开始抖** → 调回 **0.53**。
4. **总往一侧偏**（单向偏，不是画龙）→ 改零点补偿 `LINE_ERR_OFFSET` = **−2.5**（视觉零点实测 +2.5）。
5. **进弯前方向来不及纠正**：日志出现 `<<< 弯中一直偏右没回中，怀疑来不及（考虑降速）`（弯中偏差连续 `SM_LATE_FRAMES = 10` 帧、约 260 ms 还是负的）→ **降基速**（`Service.c` 里的 30/20/15），**不是加大 Kp**。

**方向环现值（11-24）**：Kp 0.15 / Kd 0.53 / D 每帧限幅 `LIMIT_LINE_DIFF_MAX` 4 / 死区 `LINE_ERR_DEADBAND` 1 格 —— 这是"十分轻微可接受的画龙"那一版，**别整体重调**。

> **硬性条件：抓的时候 MaixPy IDE 必须点「断开连接」**（不是最小化）。同一个串口只能一个人占。

### 6.4 一个完整循环（约 3 分钟）
1. 板子插 USB（不用拔卡）。
2. 列串口 → 抓 60 秒 → 从输出里抽 9 个「实」半宽 → 算新参数。
3. 定下改哪两行、改成什么 → IDE 里改那两行 → 保存到开发板。
4. 拔插 USB 重启 → 回到第 2 步。

标定阶段每轮只改 2 个数；调阈值阶段每轮改 1 个数。

### 6.5 前提与抓不到怎么办
- 卡上必须有 `main.py`，否则上电进 REPL，不跑程序。
- 波特率 **115200，8N1**；板子 USB 串口一般是 CH340（设备管理器里叫「USB-SERIAL CH340」）。
- 电脑现在有 COM3 / COM4 / COM5 / COM15 四个口，**插上板子前后对比一次**才知道哪个是它。
- 抓不到依次查：① IDE 是否点了「断开连接」 ② 端口号对不对（拔插一次对比列表） ③ 卡上有没有 `main.py` ④ 都不行 → 退回拔卡读 `run_log.txt`。

### 6.6 分工
- 列串口、抓日志、抽数、算参数、看日志找问题 → **抓数据的人**。
- 在 IDE 里改那两行、点保存 → **操作车的人**；插线、摆车、扶车、按复位也是他。
- 判断「这圈跑得行不行」→ **一起看**。

## 8 出问题时的判断顺序（症状 → 先查什么）

**一级一级往下查，前一级不对就别看后一级：**

### 第 1 级：车不动
1. 灯是不是慢闪？快闪 = 视觉没起来，启动被门禁挡住。
2. 九行是不是全 `x`？→ 车摆歪了 / 镜头被挡 / 光照不对（→ §5.1）。
3. `SEND_UART` 是不是 **True**、`SM_FUSE_M` 是不是 **2.5**？

### 第 2 级：车动但不会拐
1. 阶段一（架空）方向对不对？反了立刻停（→ §4.2）。
2. 日志里有没有"方向接管触发"？
3. 陀螺仪 `ch1` 是不是 **18**（→ §2 台架模式）。

### 第 3 级：跑完看 `run_log.txt`，先看这两件事
| 症状 | 先看什么 | 结论 |
|---|---|---|
| 出弯后偏差冻在 **−20** 长达 1.2 秒（= 12 帧一模一样） | 那 1.2 秒的九行图案 | 全是 `x` 或 `L`/`R` → 是"看不见线还沿用上次偏差"；九行都是 `#` 但偏差还是 −20 → 偏差算错了，另一回事 |
| 直道上偏差单帧跳 **34 格（16 厘米）** | 同一时刻的九行 | 某一行突然换了目标（抓到旁边的线/墙），还是整块都变 |

**看数据只有两条腿**：K210 侧靠 `RECORD_TO_FILE = True` 写 `run_log.txt` 到卡根目录，`RECORD_FLUSH_EVERY = 10`，每帧记图案、九行的段/中/实/理、偏差、远偏差、状态、发出值、已跑秒数；STM32 侧**这一趟不看**，要看走蓝牙（VOFA+ 手机端）。

### 第 4 级：还没解决的四件事（按这个顺序动）
1. **陀螺仪间歇性导致转弯 180°**（最重要）：同一个弯有时 90°、有时 180°（180 = 撞 600 毫秒超时）。看 `I3`（陀螺仪累计角度）曲线就能定性：急降 / 平 / 跳回 0 分别对应三种原因。
2. **通蓝牙遥测**：COM3 / COM4 / COM5 / COM15 全是蓝牙口，遥测本来就无线；通了就能看 `I3`（角度）、`I6`（开转里程）。
3. **硬件三件事**：上拉 **4.7 kΩ** / I2C 线远离电机线 / 电机端子并 **0.1 µF** / 陀螺仪模块插座检查。
4. **标定 3、4、5 号弯**（现在 185 / 185 / 79 是估的）。
5. **先别碰转弯参数**：那套数是眼睛一趟一趟标出来的。

## 9 禁令（一条都别破）

1. **跑车的时候，一根 USB 线都不许插。** 线会把车和电脑拴成一根绳上的蚂蚱：车跑 1 米，电脑得跟着挪 1 米。要看数据走 SD 卡或蓝牙。
2. **不许为了看波形把 STM32 的 USB 插着跑** —— 同一个坑。
3. **不许再提"手推标定"**：不许手推 294 厘米校 `CM_PER_COUNT`，不许推车走一段读编码器来标任何参数。`CM_PER_COUNT` 保持理论值 **0.01402**。
   - 13 线 × 4 倍频 = 52 计数/电机圈；减速比 1:28 → 1456 计数/轮子圈；轮径 65 毫米 → 周长 π × 6.5 = 20.42 厘米；20.42 ÷ 1456 = 0.01402。
   - 旧手推值 0.01610 高 14.8%，已确认不准。
4. **改之前不许不备份**：`git log --oneline -1` 记版本号 + 卡上 `main.py` 复制到 `F:\backup\`。
5. **抓串口时 IDE 必须点「断开连接」**（不是最小化）。IDE 开着数据传输会吃掉 5 ms：开着 28 ms / 20 帧，关掉 23 ms / 38 帧。
6. **不许单缓冲跑**：`sensor.reset(dual_buff=True)` 必须开。单缓冲 + 处理 20 ms = 19.23 帧；双缓冲 + 处理 20 ms = 38.46 帧。
7. **分界线比例不许超过 0.65**（0.55 是现值），超了地面会变黑。
8. **速度环别调了**：Kp / Ki = **100 / 10**（左右一致），积分时间 50 ms，饱和误差 10 counts，`SoftStart_Scale` 300 ms 斜坡已写进 `Service.c`。三个指标全过，再调 ±10% 看不出来。
9. **别拿读不出来的寄存器当证据**：`sensor.__read_reg` 全返回 0，那套 HTS×VTS 理论从头到尾没证据。
10. **别为了"理论上更优雅"改法**：这样的改法都会推翻那套用眼睛标出来的参数 —— 改之前先问：值不值得重标五个弯。
11. **只有实车能测的数，直接听实测加减多少，不要自己插值/推算。**
12. **评分规则记牢**：计时间；压线扣分，出线 0 分（锐角弯③用 90° 必压线）。
