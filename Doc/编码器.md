# 第 0 章 先说清楚一件事：编码器不接 TB6612

## TB6612FNG 的完整引脚

| 引脚 | 功能 | 性质 |
|---|---|---|
| VM | 电机电源（本项目 12.6 V） | 电源输入 |
| VCC | 逻辑电源（3.3 V） | 电源输入 |
| GND | 地 | 电源 |
| **AO1 / AO2** | **左电机输出** | ⚠️ 功率输出，20 kHz、12.6 V |
| **BO1 / BO2** | **右电机输出** | ⚠️ 功率输出，20 kHz、12.6 V |
| PWMA / AIN1 / AIN2 | 左电机控制 | 数字输入 |
| PWMB / BIN1 / BIN2 | 右电机控制 | 数字输入 |
| STBY | 待机使能 | 数字输入 |

**TB6612FNG 是一颗纯 H 桥（电机驱动），没有任何编码器接口。**

## 为什么"编码器接 BO1/BO2"是错的

带编码器的 TT 电机是 **6 根线**：

```
M+  红粗  ┐
M-  黑粗  ┘  →  电机电源，接 TB6612 的 AO1/AO2 或 BO1/BO2

A   细    ┐
B   细    │  →  编码器信号，接 STM32 的定时器引脚
VCC 细    │
GND 细    ┘
```

**只有前两根（粗线）接 TB6612，后四根（细线）全部接 STM32。**

若把编码器信号接到 AO1/AO2/BO1/BO2：

| 后果 | 原因 |
|---|---|
| 💀 编码器瞬间烧毁 | 12.6 V 打进 3.3 V 的霍尔/光耦 |
| 💀 TB6612 可能烧毁 | 编码器输出端顶 H 桥功率输出脚 |
| 电机完全不转 | 电机电源线被挪走 |

## 正确接线（本车）

| 从哪来 | 信号 | 接到哪 |
|---|---|---|
| 左电机 M+（红粗） | 电机电源 | **TB6612 AO1** |
| 左电机 M-（黑粗） | 电机电源 | **TB6612 AO2** |
| 左编码器 A | 编码器信号 | **PA15**（TIM2_CH1） |
| 左编码器 B | 编码器信号 | **PB3**（TIM2_CH2） |
| 编码器 VCC | 3.3 V | 3.3 V |
| 编码器 GND | 地 | GND |
| 右电机 M+（红粗） | 电机电源 | **TB6612 BO1** |
| 右电机 M-（黑粗） | 电机电源 | **TB6612 BO2** |
| 右编码器 A | 编码器信号 | **PB6**（TIM4_CH1） |
| 右编码器 B | 编码器信号 | **PB7**（TIM4_CH2） |
| 编码器 VCC | 3.3 V | 3.3 V |
| 编码器 GND | 地 | GND |

**记法：粗线走 TB6612，细线走 STM32。**

# 第 1 章 编码器的物理原理

## 1.1 霍尔编码器结构

```
        电机轴
          │
     ┌────┴────┐
     │ 多极磁环  │  ← 跟着轴转
     └────┬────┘
          │
   ┌──────┴──────┐
   │  霍尔A   霍尔B │  ← 两个霍尔元件，相距 90° 电角度
   └─────────────┘
```

## 1.2 正转 vs 反转

```
正转：  A ──┐  ┌──┐  ┌──
           └──┘  └──┘
        B ────┐  ┌──┐  ┌
              └──┘  └──┘
              ↑ A 领先 B 90°

反转：  A ────┐  ┌──┐  ┌
              └──┘  └──┘
        B ──┐  ┌──┐  ┌──
           └──┘  └──┘
              ↑ B 领先 A 90°
```

**A 和 B 的相位关系决定方向。**

## 1.3 为什么叫「4 倍频」

| 计数方式 | 每周期计数次数 | 倍频 |
|---|---|---|
| 只数 A 上升沿 | 1 | 1 倍 |
| 数 A 上升 + 下降沿 | 2 | 2 倍 |
| **A、B 的所有边沿都数** | **4** | **4 倍** |

本车用的是 `TIM_EncoderMode_TI12` = **4 倍频**。

## 1.4 硬件自动完成

`TI12` 模式下定时器**同时监视 A 和 B**，每次任一输入变化：
- 若另一路为高 → **+1**
- 若另一路为低 → **−1**

**这一切是纯硬件行为，CPU 完全不参与。**

> 这就是引脚表里写「**不占用 CPU**」的原因。

# 第 2 章 引脚宏定义

```c
/* 左编码器：TIM2 部分重映射1 -> CH1=PA15, CH2=PB3
 *   注意1：PA15/PB3 复位后默认是 JTAG 的 JTDI/JTDO，
 *          必须在 main 里先关 JTAG，再调用 Encoder_Init()
 *   注意2：PB3 硬件上必须串 1kΩ 电阻，否则插着下载器复位时会和 JTDO 对顶
 * 右编码器：TIM4 -> CH1=PB6, CH2=PB7（无重映射）
 */
```

## 2.1 为什么左轮要用「部分重映射 1」

STM32F103 的 TIM2 引脚：

| 通道 | 默认引脚 | 部分重映射1 后 | 全重映射后 |
|---|---|---|---|
| CH1 | PA0 | **PA15** | PA15 |
| CH2 | PA1 | **PB3** | PB3 |
| CH3 | PA2 | PA2 | PB10 |
| CH4 | PA3 | PA3 | PB11 |

PA0 被按键占了，所以选了部分重映射1。

## 2.2 为什么选 TIM2 和 TIM4

| 定时器 | 用途 |
|---|---|
| TIM1 | 电机 PWM（高级定时器） |
| **TIM2** | **左编码器** |
| TIM3 | 1 ms 系统时基 |
| **TIM4** | **右编码器** |

只有 TIM1~TIM8 中的 TIM2~TIM5 支持「编码器接口模式」，而 TIM3 已被时基占用。

## 2.3 PB3 为什么必须串 1 kΩ

PB3 复位后默认是 **JTDO**。插着 ST-Link 上电/复位时，JTDO 会主动驱动这根线；同时编码器也在驱动它 → **两个输出对顶**。

串 1 kΩ 后，即使对顶，电流也只有 `3.3V / 1kΩ = 3.3 mA`，不会损坏任何一方。

# 第 3 章 增量缓存

```c
static int16_t EncLeft_LastCounter = 0;
static int16_t EncRight_LastCounter = 0;
static int16_t EncLeft_DeltaCounter = 0;
static int16_t EncRight_DeltaCounter = 0;
```

## 3.1 为什么需要

定时器的计数器是**累计值**，不是**增量**：

```
t=0ms    计数器 = 1000
t=5ms    计数器 = 1050     ← 这 5ms 转了 50
t=10ms   计数器 = 1080     ← 这 5ms 转了 30
```

PID 要的是「**这一周期转了多少**」，所以必须记住上次值再相减。

## 3.2 为什么缓存而不是现算

```c
/* 增量缓存：由 Encoder_Update() 刷新，避免上层重复调用把增量清零 */
```

如果每次 `Encoder_GetDelta()` 都现算并清零，**上层调用两次就会丢数据**（第二次得 0）。

现在的设计是「一个周期算一次，之后可以反复读」。

# 第 4 章 Encoder_Init 逐段

## 4.1 关 JTAG（第 40~41 行）

```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO, ENABLE);
GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE);
```

**为什么必须做**

复位后 PA15/PB3 的默认功能是 JTAG 调试口：

| 引脚 | 默认功能 |
|---|---|
| PA13 | SWDIO |
| PA14 | SWCLK |
| **PA15** | **JTDI** |
| **PB3** | **JTDO** |
| PB4 | NJTRST |

不关 JTAG，这两根线被调试口占着，配成定时器输入也读不到。

`GPIO_Remap_SWJ_JTAGDisable` = **关掉 JTAG，保留 SWD**（仍可下载调试）。

## 4.2 TIM2 部分重映射（第 49 行）

```c
GPIO_PinRemapConfig(GPIO_PartialRemap1_TIM2, ENABLE);
```

代码注释（踩过坑的记录）：

```c
//  必须用库函数，禁止 AFIO->MAPR |= ... 这种裸寄存器写法：
//  SWJ_CFG 是只写位，读回值未定义，读-改-写会随机制造"重新上电就坏"
```

`AFIO->MAPR` 里的 `SWJ_CFG[2:0]` 是**只写位**，读回来是垃圾值。写 `AFIO->MAPR |= x` 会先读、或、再写——**把垃圾值写回去，随机破坏 JTAG 配置**。

## 4.3 引脚模式（第 52~64 行）

```c
GPIO_InitStruct.GPIO_Mode = GPIO_Mode_IPU;    // 上拉输入
```

**编码器输出有两种类型**

| 类型 | 输出方式 | 需要上拉吗 |
|---|---|---|
| 开漏输出（很多霍尔编码器） | 只能拉低 | **必须上拉** |
| 推挽输出 | 能拉高能拉低 | 不需要 |

**用上拉输入是两种都兼容的稳妥做法。**

## 4.4 时基（第 71~78 行）

```c
TIM_TimeBaseInitStruct.TIM_Period = 65535;      // ARR = 65535
TIM_TimeBaseInitStruct.TIM_Prescaler = 0;       // 不分频
```

**ARR = 65535**：16 位计数器最大值，每转满一圈才回绕一次。

**不分频**：分配频会降低分辨率。5 ms 内可能只有几十个 counts，再分频就测不准。

> **低速时分辨率越高，速度环越稳。**

## 4.5 输入滤波（第 81~83 行）

```c
TIM_ICInitStruct.TIM_ICFilter = 0xF;   // 最大滤波
```

`0xF` = 采样频率 f_DTS/32，连续 8 次一致才认。

**作用**：抑制电机换向电刷火花产生的高频干扰。

**代价**：约 1~2 µs 延迟，对 5 ms 控制周期可忽略。

## 4.6 编码器接口（第 91~92 行）

```c
TIM_EncoderInterfaceConfig(ENCODER_LEFT_TIM, TIM_EncoderMode_TI12,
                           TIM_ICPolarity_Rising, TIM_ICPolarity_Rising);
```

**`TIM_EncoderMode_TI12`** = 4 倍频（A、B 所有边沿都计数）。

**两个 `Rising`** = 两通道都不反相。若改成一个 Rising 一个 Falling，可以反转计数方向（不用改接线）。

# 第 5 章 Encoder_Update：16 位回绕技巧

```c
CurrCounter = (int16_t)TIM_GetCounter(ENCODER_LEFT_TIM);
EncLeft_DeltaCounter = (int16_t)((uint16_t)CurrCounter - (uint16_t)EncLeft_LastCounter);
EncLeft_LastCounter = CurrCounter;
```

## 5.1 问题：计数器会回绕

16 位计数器范围 0~65535，转满就回绕到 0。

```
从 65530 正转到 3：实际转了 9
朴素写法：3 − 65530 = −65527   ❌ 完全错误
```

## 5.2 解法：无符号减法 + 有符号解释

```
(uint16_t)3     = 0x0003
(uint16_t)65530 = 0xFFFA

0x0003 − 0xFFFA （无符号 16 位减法，自动模 65536）
= 0x0009 = 9

(int16_t)9 = 9   ✅ 正确
```

反转的情况：

```
从 3 反转到 65530：实际转了 −9

(uint16_t)65530 = 0xFFFA
(uint16_t)3     = 0x0003

0xFFFA − 0x0003 = 0xFFF7 = 65527（无符号）
(int16_t)0xFFF7 = −9   ✅ 正确
```

## 5.3 为什么一定正确

无符号 16 位减法的结果天然是「模 65536 的差值」，而 `int16_t` 的范围正好是 −32768~32767。

**只要一个周期内增量不超过 ±32767**，结果永远正确。

> **代码必须写 `(int16_t)((uint16_t)Curr − (uint16_t)Last)`，不能直接相减。**
> 少这层转换，会出现「每转一圈速度突然反向」的诡异 bug。

# 第 6 章 读取接口

```c
int16_t Encoder_GetDeltaLeft(void)  { return EncLeft_DeltaCounter; }
int16_t Encoder_GetDeltaRight(void) { return EncRight_DeltaCounter; }
```

**可重复读取，不会清零。**

服务层可能在多处使用同一周期值（PID、VOFA+ 波形、蓝牙调参），如果读一次就清零，后面全是 0。

还有调试接口：

```c
int16_t Encoder_GetRawLeft(void)  { return (int16_t)TIM_GetCounter(ENCODER_LEFT_TIM); }
```

直接读累计值，用于判断编码器方向、是否丢脉冲。

# 第 7 章 算一算：counts 到底代表多快

## 7.1 本车参数

| 参数 | 值 |
|---|---|
| 编码器线数 | 13 PPR（常见值，**请按实物核对**） |
| 倍频 | 4 倍频 |
| **减速比** | **1:28** |

## 7.2 每转计数

```
电机轴转一圈 = 13 × 4 = 52 counts
输出轴转一圈 = 52 × 28 = 1456 counts
```

## 7.3 换算速度

目标速度 `Speed_Straight = 40 counts/5ms`：

```
每秒计数 = 40 × (1000 / 5) = 8000 counts/s
输出轴转速 = 8000 / 1456 = 5.49 转/秒
          = 5.49 × 60 = 329.7 RPM
```

## 7.4 换算成车速

假设轮径 **65 mm**（常见 TT 电机轮，请按实物核对）：

```
轮周长 = π × 0.065 = 0.2042 m
线速度 = 5.49 × 0.2042 = 1.12 m/s = 4.04 km/h
```

## 7.5 三档基速对应

| 变量 | counts/5ms | 输出轴转速 | 线速度 |
|---|---|---|---|
| `Speed_Straight` | 40 | 329.7 RPM | 1.12 m/s |
| `Speed_SmallAngle` | 25 | 206.0 RPM | 0.70 m/s |
| `Speed_LargeAngle` | 15 | 123.6 RPM | 0.42 m/s |

## 7.6 分辨率

在 5 ms 一个周期内：

| 实际速度 | 5ms 内 counts | 量化误差 |
|---|---|---|
| 40 | 40 | ±1 count = **±2.5 %** |
| 15 | 15 | ±1 count = **±6.7 %** |

**速度越低，量化噪声占比越大**——这就是速度环不能加 D 项的核心原因。

# 第 8 章 常见故障排查

## 8.1 完全读不到数（一直 0）

| # | 检查 |
|---|---|
| 1 | **编码器 VCC/GND 接了吗**（很多人只接 A/B） |
| 2 | **JTAG 关了吗**（PA15/PB3 不关 JTAG 读不到） |
| 3 | A/B 是不是接到了 STM32（不是 TB6612） |
| 4 | 电机转的时候，`Encoder_GetRaw()` 的值会不会变 |
| 5 | PB3 的 1 kΩ 电阻装了吗 |

## 8.2 数值乱跳

| 现象 | 原因 |
|---|---|
| 每转一圈速度突变一次 | **回绕处理写错了**（少 `uint16_t` 转换） |
| 一直抖 | 滤波值太小，或引脚接触不良 |
| 偶尔出现极大值 | 编码器电源不稳，或地线没共好 |

## 8.3 方向反了

三种改法：

| 方法 | 做法 |
|---|---|
| **软件最简单** | 在 `Service.c` 里把 `actual` 取负 |
| 改极性 | `TIM_ICPolarity_Rising` 改一个成 `Falling` |
| 改接线 | 把 A/B 两根线对调 |

## 8.4 左右轮速度不一样

| 原因 | 处理 |
|---|---|
| 两个电机本身有差异 | 正常，用 PID 各自闭环 |
| 编码器线数不同 | 换同型号 |
| 减速比不同 | 换同型号 |
| 轮子直径不同 | 量一下 |
