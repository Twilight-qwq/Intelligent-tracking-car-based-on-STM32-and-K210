## 一、帧率（K210 + OV5642）

### 1.1 分辨率扫描（`fps_probe.py` v3，双缓冲，不处理）

| 分辨率 | 帧率 | 一帧 | 想要=实际 |
|---|---|---|---|
| 80×60 | 19.23 | 52.0 ms | ✓ |
| 160×120 | 19.23 | 52.0 ms | ✓ |
| **320×240** | **38.46** | **26.0 ms** | ✓ |
| **640×480** | **38.46** | **26.0 ms** | ✓ |
| 切回 160×120 | 19.22 | 52.0 ms | ✓ |

**640×480 的像素是 320×240 的 4 倍，帧率一样** → 限制不在读出时间。

### 1.2 其它方向的对照（`fps_probe.py` v2）

| 配置 | 帧率 |
|---|---|
| A 默认（freq 24MHz，单缓冲）| 19.23 |
| B `freq=27MHz` | 19.23 |
| C `dual_buff=True`（空转）| 19.23 |
| D 27MHz + 双缓冲 | 19.23 |
| E `set_framerate(60)` | 19.23 |
| **F 320×240** | **38.46** |

→ `freq`、`set_framerate`、单独开双缓冲，**全部无效**。

### 1.3 双缓冲的决定性实验（`fps_quick.py`）

| 条件 | 帧率 |
|---|---|
| 单缓冲 + 不处理 | 38.46 |
| **单缓冲 + 每帧处理 20 ms** | **19.23** |
| 双缓冲 + 不处理 | 38.46 |
| **双缓冲 + 每帧处理 20 ms** | **38.46** |

### 1.4 裁剪不改变模式（`qqvga_probe.py`）

| 配置 | 实际拿到 | 帧率 |
|---|---|---|
| 160×120 双缓冲 不处理 | 160×120 | 19.23 |
| 160×120 双缓冲 处理 6ms | 160×120 | 19.16 |
| 320×240 双缓冲 不处理 | 320×240 | 38.46 |
| 320×240 + `set_windowing((0,60,320,120))` | 320×120 | **38.46** |
| 320×240 + `set_windowing((80,60,160,120))` | **160×120** | **38.46** |

**帧率是"模式"的属性，`set_windowing` 裁剪不改模式。**

### 1.5 寄存器

`sensor.__read_reg(0x380c/0x380d/0x380e/0x380f/0x3035/0x3036)` **全部返回 0x00**，不可用。
（`fps_probe` 里试过 `__read_reg` / `read_reg` / `_read_reg` 三个名字，只有第一个存在，但读出全 0。）

## 二、处理耗时（`qvga_check.py`）

| 分辨率 | 5 行扫一遍（304 像素/行）| 每像素 |
|---|---|---|
| 160×120 | 6.03 ms | 7.9 µs |
| **320×240** | **11.80 ms** | **7.76 µs** |

比例 1.95，像素数比例 2.0 —— 完全线性。

**9 行全宽（2736 像素）实测 `用时 22.9 ms`**（关数据传输），与 2736 × 7.76 = 21.2 ms + 1.7 ms 开销吻合。

**IDE 开着"数据传输"时 `用时 27.5~30.1 ms`，帧率掉到 20~21。**

## 八、速度环台架数据

### 8.1 电机上限

- 左右电机空载极限都是 **37 counts/5ms**（1.04 m/s），再高上不去。
- 带载（Kp 扫描时，目标 27）：实际只稳在 **22**，占空比 1000‰ → 怀疑带载上限 ≈ 22（0.62 m/s）。

### 8.2 Kp 扫描（Ki=0，目标 37，空载）

| Kp | 稳态停在 | 纯 P 理论 |
|---|---|---|
| 80 | 20 | 20.2 ✓ |
| 100 | 22 | 21.3 |
| 200 | 22 | 23.8 |
| 400 | 22 | 25.3 |

**Kp ≥ 100 全部卡在 22** → 撞到某个上限（当时以为是电机上限，后来发现是空载 37，说明那次是带载状态）。

### 8.3 时间常数

目标 37（空载极限），从 0 爬到 36（97%）用 **140 ms**：
`140 ÷ 3.6 = 38.8 ms` → **τ ≈ 39 ms**。

### 8.4 Ki 对比（Kp=100）

| Ki | 积分时间 | 过冲 |
|---|---|---|
| 20 | 25 ms | **3~4 counts** |
| **10** | **50 ms** | **0** |

**Ki=10 定稿。**

### 8.5 六组阶跃（Kp=100, Ki=10）

| 阶跃 | 到位时间 | 过冲 |
|---|---|---|
| 30→20 | 20 ms | −1 |
| 20→30 | 40 ms | 0（Ki=10 后）|
| 30→10 | 25 ms | −2 |
| 10→30 | 60 ms | 0 |
| 30→15 | 30 ms | 0 |
| 15→30 | 55 ms | 0 |

**加速 40~60 ms，刹车 20~30 ms** —— 反电动势导致的不对称。

在 30 counts（37 的 81%）处：加速扭矩 ∝ (V − 反电动势) = 0.19V，刹车 ∝ (V + 反电动势) = 1.81V，**差 9.5 倍**。
在 15 counts 处只差 **2.4 倍**。
