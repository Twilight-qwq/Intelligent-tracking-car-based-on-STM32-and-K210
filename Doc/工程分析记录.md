## 1 三个点的定义（沿行进方向，第一个弯的里程）

- **内拐点** = 内侧线拐弯处 = 拐角正方形近边，里程 **160**
- **C** = 中心线拐点 = 拐角正方形中心，里程 **180** ← **说「弯口」一律指 C**
- **外拐点** = 外侧线拐弯处，里程 **200**

外拐点比 C 靠前 `20 × tan(θ/2)`，20 = 外线到中心线的横向距离（车道半宽 40 ÷ 2）。

## 2 两个公式（同源于 tan(θ/2)）

- **窗口宽度** = `20 × tan(θ/2)`：90°→20.0　103°→25.1　38.5°→7.0（cm）
- **理想开转点** = C 之前 `R × tan(θ/2)`：R 理论 7.2 / 实测折算 10.0 / 取中值 **8.5** → 90° 弯提前 8.5 cm

## 3 视觉判弯的真条件（与代码注释不符）

- `good_rows()` = 从最近那行起**连续**有几个 `#`，碰第一个非 0 就停
- **触发 = `good_rows` 变 0**（最近那行坏），再叠 `SM_PRE_FRAMES=4` + `SM_CONFIRM_FRAMES=2`
- 代码注释写"最近 3 行全丢"，**实际只要最近 1 行坏**
- 11-20 日志：锐角弯处最近几行丢掉的记录 5728 条，84.6% 是 `x`（一条都没认出）→ `SM_MIN_SINGLE` 1→0

## 4 为什么报弯比走到内拐点还早

最近那行看车前 **27.7 厘米**；内拐点进入该行视野时车在 **132.3**；再撑 6 帧（166ms，30 档走 14cm）→ 车到 **146** 才报弯，此时 C 还在前方 34 厘米。

**弯道状态机分两半**（文件头有说明）：
- 30ms（有视觉帧才跑）：`Task_CornerDecide(state)` —— **认不认这个弯**，返回 1 = 已接管
- 5ms（不依赖视觉）：`Task_5ms_CornerStep(curr_ms)` —— **什么时候开转 / 转够了没有**
- 目标速度只有一处赋值：`Corner_SetTarget(kind)`，四种 `CORNER_T_*`
- 为什么必须分开：弯里 47.5% 的帧好行=0，视觉一黑 30ms 任务第一句就 return；转弯停不下来会一直转（240°/秒）

**v2 相对 v1 的唯一行为差异**：Armed→Active 那一刻就切转弯差速（提前最多 30ms ≈ 1.3cm）。

**App 层不许直接碰硬件**：按键读电平走 `Key_IsDown()`（bsp_key）。只剩 `NVIC_PriorityGroupConfig` 仍在 App，用户说无所谓。

   - 为什么 50 够：转完一个弯，段内里程清零；下一个钝角弯的门开在 110−30 = **80 厘米**（清零后的里程）。
