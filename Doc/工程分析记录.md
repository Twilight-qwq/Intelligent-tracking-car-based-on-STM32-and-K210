## 1 三个点的定义（沿行进方向，第一个弯的里程）

- **内拐点** = 内侧线拐弯处 = 拐角正方形近边，里程 **160**
- **C** = 中心线拐点 = 拐角正方形中心，里程 **180** ← **说「弯口」一律指 C**
- **外拐点** = 外侧线拐弯处，里程 **200**

外拐点比 C 靠前 `20 × tan(θ/2)`，20 = 外线到中心线的横向距离（车道半宽 40 ÷ 2）。

## 2 两个公式（同源于 tan(θ/2)）

- **窗口宽度** = `20 × tan(θ/2)`：90°→20.0　103°→25.1　38.5°→7.0（cm）
- **理想开转点** = C 之前 `R × tan(θ/2)`：R 理论 7.2 / 实测折算 10.0 / 取中值 **8.5** → 90° 弯提前 8.5 cm

## 3 视觉判弯的真条件（与代码注释不符）

- `good_rows()` = 从最近那行起**连续**有几个 `#`，碰第一个非 0 就停
- **触发 = `good_rows` 变 0**（最近那行坏），再叠 `SM_PRE_FRAMES=4` + `SM_CONFIRM_FRAMES=2`
- 代码注释写"最近 3 行全丢"，**实际只要最近 1 行坏**
- 11-20 日志：锐角弯处最近几行丢掉的记录 5728 条，84.6% 是 `x`（一条都没认出）→ `SM_MIN_SINGLE` 1→0

## 4 为什么报弯比走到内拐点还早

最近那行看车前 **27.7 厘米**；内拐点进入该行视野时车在 **132.3**；再撑 6 帧（166ms，30 档走 14cm）→ 车到 **146** 才报弯，此时 C 还在前方 34 厘米。

**弯道状态机分两半**（文件头有说明）：
- 30ms（有视觉帧才跑）：`Task_CornerDecide(state)` —— **认不认这个弯**，返回 1 = 已接管
- 5ms（不依赖视觉）：`Task_5ms_CornerStep(curr_ms)` —— **什么时候开转 / 转够了没有**
- 目标速度只有一处赋值：`Corner_SetTarget(kind)`，四种 `CORNER_T_*`
- 为什么必须分开：弯里 47.5% 的帧好行=0，视觉一黑 30ms 任务第一句就 return；转弯停不下来会一直转（240°/秒）

**v2 相对 v1 的唯一行为差异**：Armed→Active 那一刻就切转弯差速（提前最多 30ms ≈ 1.3cm）。

**App 层不许直接碰硬件**：按键读电平走 `Key_IsDown()`（bsp_key）。只剩 `NVIC_PriorityGroupConfig` 仍在 App，用户说无所谓。

**原理**：

- `I3` 是积分器，每 5 毫秒把「转速 × 0.005 秒」加进去，输入不是严格 0 就一直爬
- 零偏**只在上电后那 1 秒采一次**，之后再也不更新；而用户上电时正在摆车，摆车的转动会被平均进零偏
- ±1 度/秒的死区是按**每一拍的转速**挡的。零偏误差一旦超过 1 度/秒，死区整个失效，**每一拍都积进去**

**加的新机制**：每 0.5 秒看一次窗口（100 个样本）里原始读数的极差，
小于 40 计数（≈0.6 度/秒）就判「车没动」→ 把这 0.5 秒的平均值当新零偏 + 把累计角度清零。

**当天就栽了一次（血的教训）**：

第一版**没有开关**，只要「0.5 秒内读数几乎不动」就重估零偏并把角度清零。
实车马上出事：车贴内侧线进弯、原地打转被卡住、**根本转不动**，陀螺仪读数就是「几乎不动」
→ 被判成静止 → 累计角度被清零 → **永远到不了 78 度** → 转弯只能等 600 毫秒超时
→ 实测转了 **135 度**，同时「进弯偏右贴内侧线」。

**修法**：加总开关 `Gyro_SetStillTrim(1/0)`，由 `AppTask_100ms` 按 `CarRun_State` 调用：

- `CarRun_State == 0`（停车）→ 允许，I3 会自动归零、不再乱爬
- `CarRun_State != 0`（在跑）→ 禁止，跑车期间一次都不触发

**教训**：任何「自动重估 / 自动校准」的机制，都必须有一个「现在允许不允许」的开关，
而且这个开关要由控制层按运行状态给。不能靠「看起来静止」去猜。

**假设它是 0（没加）**，那么钝角弯实际用的是第 1 个弯的参数：

- 阈值 = **189** → 开转点 = 189 − 10.7 = **178.3 厘米**（第 1 个弯到第 2 个弯只有约 110 厘米）
  → 车会冲到钝角弯后面 68 厘米才转 → **「已经过了钝角弯才开始转」✓**
- 角度 = **78°** → 加惯性约 90° → **「转了 75~90°」✓**
- 改 `Turn_ThresholdCm[1]`（95/88）→ 完全不影响 → **「一动不动」✓**
- 关掉 `TURN_ARM_CM` → 反正走的是强转，也不影响 → **「还是没反应」✓**

**一个假设同时解释全部四个现象。** 这是目前最强的解释。

### 23.4 方案（按顺序做，每步都能定性）

**方案 A（首选，一趟定性，不用改代码，只要蓝牙通）**

1. 车通电、**手机上的 VOFA+ / 蓝牙串口助手断开**
2. 电脑上抓 `COM15`（蓝牙口），跑一趟，看 `I6`（开转里程）：
   - `I6 ≈ 178.3` → 用的就是第 1 个弯的阈值 → **下标卡在 0，假设成立**
   - `I6 ≈ 99.3`（阈值 110 时）或 `77.3`（阈值 88 时）→ 用的确实是第 2 个弯 → 假设推翻，另找
   - `I6 ≈ 229.3`（阈值 240）→ 下标跑过头了，变成第 3 个弯
   - `I6 = −999` 或 0 → 陀螺仪/遥测没起来，先解决这个
3. 顺带看 `I3`（陀螺仪累计角）：钝角弯如果真的是 33.5°，`I3` 峰值应该是 `−40` 左右；
   如果是 `−90`，就是 78° 那条命令。

**方案 B（蓝牙一时通不上的备选，一趟也能定性，改 2 个数）**

把「所有自动转弯」全部关掉，看车还会不会在弯里转：

- `TURN_ALLOW_FORCE` 1 → **0**
- `TURN_ARM_CM` 16 → **999**（保持关掉）

跑一趟，只看一件事：**车在弯里还会不会自己转 90°？**

- **还会转** → 那这个转动跟弯道状态机**完全无关**，是方向环跟着弯道磨出来的。
  这时整台「弯道状态机」就是白写的，要重新想（方向环极限就是 56 厘米/秒下每分钟……）；
- **不转了，直着冲过去** → 证明状态机确实是转动的来源，回到方案 A 查下标。

**方案 C（如果方案 A 确认是下标卡住）**

在转弯结束、`Corner_Index++` 的那一段加保护，并且**加一个能被看见的证据**——现在的问题是没有任何
不插线就能读到的东西。最小可行做法：停车时把 `Corner_Index` 用板载灯闪出来（闪 N 下 = 索引 N），
这样跑完看一眼灯就知道走到第几个弯了。
