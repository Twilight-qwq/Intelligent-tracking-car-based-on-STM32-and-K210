## 1 三个点的定义（沿行进方向，第一个弯的里程）

- **内拐点** = 内侧线拐弯处 = 拐角正方形近边，里程 **160**
- **C** = 中心线拐点 = 拐角正方形中心，里程 **180** ← **说「弯口」一律指 C**
- **外拐点** = 外侧线拐弯处，里程 **200**（`Doc/赛道数据.md` 原来量的是这个）

外拐点比 C 靠前 `20 × tan(θ/2)`，20 = 外线到中心线的横向距离（半个车道宽 40 ÷ 2）。

---

## 2 两个公式（都来自同一个 tan(θ/2)）

- **转弯窗口宽度** = `20 × tan(θ/2)`
  90° → **20.0**　103° → **25.1**　38.5° → **7.0**（厘米）
- **最理想开转点** = C 之前 `R × tan(θ/2)`，R = 转弯半径
  R 理论 **7.2** 厘米（左 26.55 档 / 右 3.45 档 → 转率 337°/秒，中心 42.1 厘米/秒）
  R 实测折算 **10.0** 厘米（1730 计数转 90° → 240°/秒）
  取中值 **8.5** → 90° 弯要提前 **8.5** 厘米开始转

推导：`tan(θ/2) = 横向距离纵向错位 ÷ 横向距离`；圆弧切点同理 `tan(θ/2) = R ÷ T`。

## 7 遥测（蓝牙发出去的那 7 个通道，10 Hz，USART2/DMA）

`TELEMETRY_MODE = 0`（跑车，默认）：
`I0/I2` 左右轮目标速度　`I1/I3` 左右轮实际速度　`I4` 视觉偏差
**`I5` = 报弯里程（锁存）　`I6` = 开转里程（锁存）**

其它三种模式见 `Service.c` 里 `Task_SendTelemetry()` 的注释。

**两个锁存值在事件瞬间存下**，不是 100 ms 采样（采样误差会到 7 厘米，而窗口只有 20 厘米）。

## 8 K210 日志新增字段（2026-11-22）

每行图案日志末尾：`... | 里=1234 弯=2`

- `里=` 估算里程（厘米）= Σ 档位名义速度 × 帧间隔
- `弯=` 上电以来「进入状态 2」的累计次数

**用途**：和 STM32 的「报弯里程 / 开转里程」按**第几个弯**配对，不需要同一个时钟。

## 11 代码结构（2026-11-22 重构，提交 `5236ac2`）

```
Control/
  APP/Src  app_control.c    所有「车怎么跑」的逻辑，一拍干一次活
           app_scheduler.c  只管节拍：到点了没有；到点就调 app_control 对应那一拍
  APP/Inc  app_control.h    6 个函数：Init / 5ms / 10ms / 30ms / 100ms / Clock
           app_scheduler.h  主循环用的 6 个：Service_Init / Idle / 5ms / 10ms / 30ms / 100ms
  MID/Src  mid_delay.c  mid_pid.c  mid_protocol.c     （Inc 同名 .h）
  BSP/Src  bsp_bluetooth  bsp_encoder  bsp_gyro  bsp_indicatorled  bsp_key
           bsp_motor  bsp_receiverk210  bsp_systimer  bsp_voice  bsp_watchdog
  DebugLayer/Debug.c
  User/main.c              只 include app_scheduler.h
```

- **主循环调谁**：`ServiceTask_Idle` / `_5ms` / `_10ms` / `_30ms` / `_100ms`（都在 app_scheduler.c）
- **四个任务的闹钟**（`task_last_5ms` 等）也搬到了 app_scheduler.c
- **台架标定**从 5 毫秒任务里抽成了 `Task_EncoderCalib()`，返回 1 = 正在标定、这一拍别跑车
- **依赖方向**：scheduler → control → BSP/MID。反向没有
- 改名后 Keil 的 IncludePath 不用动（`APP/MID/BSP` 三个目录没变），只改了文件列表
