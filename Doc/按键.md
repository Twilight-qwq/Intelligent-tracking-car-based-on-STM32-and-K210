# 第 0 章 职责与链路

**一句话：把"物理按键被按下"这个事件，转换成一个可以查询的标志位。**

```
手指按下去（机械动作）
    ↓
PA0 引脚电平从 1 变 0（并伴随 5~20ms 的抖动）
    ↓
Key_CheckRequest() 每 10ms 检查一次，做消抖
    ↓
Key_Request = 1
    ↓
Key_GetRequest() 被 Service.c 取走，取走后清零
    ↓
CarRun_State 翻转（启动 / 停止）
```

# 第 1 章 硬件

## 1.1 引脚定义

```c
#define KEY_CLK             RCC_APB2Periph_GPIOA
#define KEY_PORT            GPIOA
#define KEYA_PIN            GPIO_Pin_0   // 原为 PA8，与左轮 PWM(TIM1_CH1) 撞脚，已挪到 PA0
```

## 1.2 配置

```c
GPIO_InitStruct.GPIO_Mode  = GPIO_Mode_IPU;      // 上拉输入
GPIO_InitStruct.GPIO_Pin   = KEYA_PIN;
GPIO_InitStruct.GPIO_Speed = GPIO_Speed_50MHz;
GPIO_Init(KEY_PORT, &GPIO_InitStruct);
```

## 1.3 接线

```
        3.3V
          │
       ┌──┴──┐  ← 芯片内部上拉电阻（IPU 模式）
       │     │
PA0 ───┘     │
       │     │
     按键     │
       │     │
      GND ───┘
```

| 按键状态 | PA0 电平 |
|---|---|
| **松开** | 上拉 → **1** |
| **按下** | 通 GND → **0** |

**所以代码里判断"按下"是 `current_level == 0`。**

## 1.4 历史坑：PA8 撞脚

```c
// 原为 PA8，与左轮 PWM(TIM1_CH1) 撞脚，已挪到 PA0
```

**PA8 是 TIM1_CH1（左轮 PWM）。** 曾经按键和 PWM 抢同一根引脚——按键会把 PWM 拉低，电机就抖。

**挪到 PA0 后解决。**

> **教训：STM32 的引脚是复用的，加新功能前必须核对"这根脚还有谁在用"。**

# 第 2 章 三个状态变量

```c
static uint8_t  Key_Request    = 0;    //待处理的按键事件(0=无 1=有一次按下)
static uint8_t  KeyStableLevel = 1;    //已确认的稳定电平(1=松开 0=按下)
static uint8_t  KeyLastSample  = 1;    //上一次采样值,用于判断电平是否变化
static uint32_t KeyA_Ticks     = 0;    //采样值最后一次变化的时刻
```

四个变量，四句话：

| 变量 | 类型 | 初值 | 含义 |
|---|---|---|---|
| `Key_Request` | `uint8_t` | 0 | **事件标志**，`Key_GetRequest` 读后清零 |
| `KeyStableLevel` | `uint8_t` | 1 | **已确认**的稳定电平（这个才是"当前按键状态"） |
| `KeyLastSample` | `uint8_t` | 1 | **上一次采样值**，用于判断"电平有没有变化" |
| `KeyA_Ticks` | `uint32_t` | 0 | 用于计时的时刻戳 |

## 2.1 为什么需要两个"电平"变量

| 角色 | 用途 | 变化频率 |
|---|---|---|
| **`KeyLastSample`** | 判断"要不要重置计时器" | 每 10ms 可能变 |
| **`KeyStableLevel`** | 判断"要不要提交事件" | 只在确认稳定后变 |

**这两个变量分工明确，缺一不可。** 详见第 5 章的历史 bug。

## 2.2 `static` 的作用

**这四个变量只在本文件可见。** 外部不能直接改，只能通过三个函数：

```c
void    Key_Init(void);
void    Key_CheckRequest(uint32_t current_tick);
uint8_t Key_GetRequest(void);
```

**好处**：状态封装，外部改不坏。

## 2.3 为什么不需要 `volatile`

```c
static uint8_t Key_Request = 0;
```

**这些变量只在主循环里读写，不在中断里。** 所以不需要 `volatile`。

对比 `SysTicks`（中断里改、主循环里读）就必须加 `volatile`。

# 第 3 章 为什么必须消抖

## 3.1 机械按键的波形

```
理想（你以为的）：
  松开 ──────┐
             └────────── 按下

实际（物理世界的）：
  松开 ──┐ ┌┐ ┌───┐
         └─┘└─┘   └──── 按下
           ↑ ↑ ↑
         抖动 5~20ms，被读成 3~5 次
```

## 3.2 不消抖会怎样

假设你按下按键：

```
第 1 次读：0 → 认为按下 → 车启动
第 2 次读：1 → 认为松开 → 无动作
第 3 次读：0 → 认为按下 → 车停止
第 4 次读：1 → 无动作
第 5 次读：0 → 认为按下 → 车启动
```

**一次按键，车反复启停 3 次。** 这是不能接受的。

## 3.3 消抖的本质

> **只在电平"稳定保持一段时间"之后，才承认它变了。**

# 第 4 章 消抖算法（正确版）

```c
void Key_CheckRequest(uint32_t current_tick)
{
    uint8_t current_level = GPIO_ReadInputDataBit(KEY_PORT, KEYA_PIN);

    //1.采样值与上次不同 -> 重新开始计时
    if (current_level != KeyLastSample)
    {
        KeyA_Ticks    = current_tick;
        KeyLastSample = current_level;
    }

    //2.连续 20ms 采样值没变 -> 认为电平真的稳定了
    if ((current_tick - KeyA_Ticks) >= 20)
    {
        //3.稳定电平与"已确认电平"不同 -> 提交这次变化
        if (current_level != KeyStableLevel)
        {
            KeyStableLevel = current_level;
            if (current_level == 0)      //低电平 = 按下
            {
                Key_Request = 1;
            }
        }
    }
}
```

## 4.1 三步逻辑

| 步 | 判断 | 动作 |
|---|---|---|
| **①** | 采样值和上次不同？（电平在动） | **重置计时器** |
| **②** | 计时器已经过了 20ms？（电平不动了） | 继续 |
| **③** | 稳定的电平和已确认的不一样？ | **提交，更新 `KeyStableLevel`** |

## 4.2 完整推演（按下过程，10ms 调一次）

初始：`KeyLastSample=1`，`KeyStableLevel=1`，`KeyA_Ticks=0`

| 时刻 | 电平 | ① 执行？ | `KeyA_Ticks` | ② 成立？ | ③ 执行？ | `Key_Request` |
|---|---|---|---|---|---|---|
| t=0（松开） | 1 | 否（1==1） | 0 | 是 | 否（1==1） | 0 |
| t=100（按下） | **0** | ✅ 是 | **100** | 否（0≥20 假） | — | 0 |
| t=110 | 0 | 否（0==0） | 100 | 否（10≥20 假） | — | 0 |
| t=120 | 0 | 否 | 100 | ✅ **是** | ✅ **是** | **1** ✅ |

**按下后 20ms 触发一次。**

## 4.3 按住不放会重复触发吗

从 t=120 之后：

| 时刻 | 电平 | ① | ② | ③ | `Key_Request` |
|---|---|---|---|---|---|
| t=130 | 0 | 否 | 是 | 否（0==0） | 保持 1 |
| t=200 | 0 | 否 | 是 | 否 | 保持 1 |
| t=1000 | 0 | 否 | 是 | 否 | 保持 1 |

**因为 `KeyStableLevel` 已经是 0，③ 不再成立 → 不会重复触发。** ✅

## 4.4 松开时会不会误触发

| 时刻 | 电平 | ① | ② | ③ | `Key_Request` |
|---|---|---|---|---|---|
| t=2000（松开） | **1** | ✅ 是 | 否 | — | 不变 |
| t=2020 | 1 | 否 | ✅ 是 | ✅ 是（1≠0） | `KeyStableLevel=1`，**但不置 `Key_Request`**（只有 0 才置） |

**松开只更新状态，不触发事件。** ✅

# 第 5 章 曾经的 bug（重要教训）

## 5.1 原始代码

```c
static uint8_t  Key_Request    = 0;
static uint8_t  KeyAPastLevel  = 1;    // ← 一个变量扛了两个职责
static uint32_t KeyA_Ticks     = 0;

void Key_CheckRequest(uint32_t current_tick)
{
    uint8_t current_level = GPIO_ReadInputDataBit(KEY_PORT, KEYA_PIN);

    if (current_level != KeyAPastLevel)      // ① 变了就计时
    {
        KeyA_Ticks = current_tick;
    }

    if ((current_tick - KeyA_Ticks) >= 20)   // ② 稳定 20ms
    {
        if (current_level != KeyAPastLevel)  // ③ 再确认
        {
            KeyAPastLevel = current_level;
            if (current_level == 0)
            {
                Key_Request = 1;
            }
        }
    }
}
```

**看起来逻辑很合理，实际上按键永久失效。**

## 5.2 推演

| 时刻 | 电平 | `KeyAPastLevel` | ① 执行？ | `KeyA_Ticks` | ② 成立？ |
|---|---|---|---|---|---|
| t=100（按下） | **0** | 1 | ✅ 是 | **=100** | 否（0≥20 假） |
| t=110 | **0** | 1 | ✅ 是 | **=110** | 否 |
| t=120 | **0** | 1 | ✅ 是 | **=120** | 否 |
| t=130 | **0** | 1 | ✅ 是 | **=130** | 否 |
| … | … | … | **永远执行** | **永远=当前时刻** | **永远不成立** |

## 5.3 死循环

```
① 执行  ← 因为 current_level != KeyAPastLevel
    ↓
KeyA_Ticks 被清成当前时刻
    ↓
② 的差值恒为 0，永远 < 20
    ↓
③ 永远不执行 → KeyAPastLevel 永远不更新
    ↓
current_level 永远 != KeyAPastLevel
    ↓
回到 ①，继续执行
```

**`Key_Request` 永远是 0 → 按键完全无效。**

## 5.4 根因

**一个变量扛了两个职责：**

| 需要的角色 | 原始代码由谁承担 |
|---|---|
| **上一次采样值**（判断"有没有变化"） | `KeyAPastLevel` |
| **已确认的稳定电平**（判断"要不要提交"） | `KeyAPastLevel`（同一个） |

**同一个变量不能既当"候选"又当"已确认"。**

## 5.5 修复

**拆成两个变量：**

```c
static uint8_t KeyStableLevel = 1;   // 已确认
static uint8_t KeyLastSample  = 1;   // 上次采样（新增）
```

```c
if (current_level != KeyLastSample)   // 用"采样值"判断变化
{
    KeyA_Ticks    = current_tick;
    KeyLastSample = current_level;    // ← 关键：更新采样值
}

if ((current_tick - KeyA_Ticks) >= 20)
{
    if (current_level != KeyStableLevel)   // 用"稳定值"判断提交
    {
        KeyStableLevel = current_level;
        ...
    }
}
```

## 5.6 这类 bug 的通用特征

| 特征 | 说明 |
|---|---|
| **编译不报错** | 语法完全正确 |
| **不崩溃** | 只是行为错误 |
| **难以察觉** | 表现是"功能没反应"，容易怀疑硬件 |
| **根因是状态机设计** | 一个变量承担多重语义 |

> **写状态机时，先列出"需要记住哪些状态"，每个状态一个变量，不要复用。**

# 第 6 章 逐行讲解

## 6.1 读电平

```c
uint8_t current_level = GPIO_ReadInputDataBit(KEY_PORT, KEYA_PIN);
```

返回 `Bit_SET`（1）或 `Bit_RESET`（0）。

**这只读一次**，后面所有判断都用这个快照——避免在函数内部两次读之间电平变化造成不一致。

## 6.2 变化检测与计时

```c
if (current_level != KeyLastSample)
{
    KeyA_Ticks    = current_tick;
    KeyLastSample = current_level;
}
```

**两个动作必须成对：**

| 动作 | 作用 |
|---|---|
| `KeyA_Ticks = current_tick` | 重置计时器（抖动期间不断重置） |
| `KeyLastSample = current_level` | **更新采样值，防止下一拍又进这个分支** |

**只做前一个 → 就是第 5 章的 bug。**

## 6.3 稳定判定

```c
if ((current_tick - KeyA_Ticks) >= 20)
```

**为什么用 `>=` 而不是 `==`：**

调用周期是 10ms，计时值可能是 10、20、30……

如果写 `== 20`，某次因为中断延迟跳到 30 就直接错过了。

**用 `>=` 永远不会漏。**

## 6.4 提交

```c
if (current_level != KeyStableLevel)
{
    KeyStableLevel = current_level;

    if (current_level == 0)      //低电平 = 按下
    {
        Key_Request = 1;
    }
}
```

**注意：只有"按下"才置 `Key_Request`，松开只更新状态。**

| 事件 | 更新 `KeyStableLevel` | 置 `Key_Request` |
|---|---|---|
| 按下（1→0） | ✅ | ✅ |
| 松开（0→1） | ✅ | ❌ |

# 第 7 章 消费型接口

```c
uint8_t Key_GetRequest(void)
{
    if (Key_Request == 1)
    {
        Key_Request = 0;    // ★ 读后清零
        return 1;
    }
    return 0;
}
```

## 7.1 "消费型" vs "生产型"

| 类型 | 行为 | 本工程例子 |
|---|---|---|
| **消费型** | 读一次就清掉 | `Key_GetRequest()`、`Voice_GetCommand()` |
| **生产型** | 读后不清零，可重复读 | `Encoder_GetDeltaLeft()`、`SysTimer_GetTick()` |

**怎么选：**

- **事件**（一件事发生了一次）→ 消费型
- **测量值**（持续存在的量）→ 生产型

**按键是事件，所以用消费型。**

## 7.2 为什么不直接返回 `Key_Request`

```c
// ❌ 错误：外部读到 1 之后不清零，会一直读到 1
uint8_t Key_IsPressed(void) { return Key_Request; }
```

**`Task_StartStopCmd` 每 100ms 调一次，如果不清零，车会每 100ms 启停一次。**

# 第 8 章 调用位置与参数

## 8.1 调用位置

```c
// Service.c
void ServiceTask_10ms(uint32_t curr_ms)
{
    if(curr_ms - task_last_10ms < 10) return;
    task_last_10ms = curr_ms;
    Key_CheckRequest(curr_ms);        // ← 每 10ms 调一次
}
```

```c
// Service.c
static void Task_StartStopCmd(void)
{
    if(Key_GetRequest() == 1)          // ← 每 100ms 查一次
    {
        CarRun_State = !CarRun_State;
    }
}
```

## 8.2 参数评价

| 参数 | 值 | 评价 |
|---|---|---|
| 检查周期 | 10 ms | ✅ 够快 |
| 消抖阈值 | 20 ms | ⚠️ **偏小**，只相当于"连续 2 次采样一致" |
| 典型机械按键抖动 | 5~20 ms | 可能刚好卡在边界 |

**建议 30~50ms 更稳**（人按下按键会保持 100ms 以上，不会有延迟感）。

**但当前 20ms 可用，不必改。**

## 8.3 为什么不用 EXTI 外部中断

**技术上可以**（PA0 支持 EXTI0），但：

| 方式 | CPU 占用 | 消抖 | 复杂度 |
|---|---|---|---|
| **轮询（现在）** | 每 10ms 查一次，几乎为 0 | 软件消抖，简单 | 低 |
| EXTI 中断 | 每次抖动都触发中断 | 中断里还得软件消抖 | 高 |

**轮询更简单、更稳。10ms 的响应延迟人感觉不到。**

## 8.4 为什么 `KeyA_Ticks` 用 `uint32_t`

因为要接收 `SysTimer_GetTick()` 的返回值（32 位毫秒）。

**减法 `(current_tick - KeyA_Ticks)` 天然免疫 49.7 天回绕**（无符号减法自动模 2³²）。

# 第 9 章 扩展：加第二个按键

现在的代码是"硬编码单个按键"，加第二个要复制一遍逻辑。

## 9.1 结构体数组写法

```c
typedef struct {
    GPIO_TypeDef *port;
    uint16_t      pin;
    uint8_t       stable;
    uint8_t       last;
    uint32_t      ticks;
    uint8_t       request;
} key_t;

static key_t keys[2] = {
    { GPIOA, GPIO_Pin_0, 1, 1, 0, 0 },
    { GPIOA, GPIO_Pin_1, 1, 1, 0, 0 },
};

void Key_CheckRequest(uint32_t now)
{
    uint8_t i;
    for (i = 0; i < 2; i++)
    {
        uint8_t lv = GPIO_ReadInputDataBit(keys[i].port, keys[i].pin);

        if (lv != keys[i].last)
        {
            keys[i].ticks = now;
            keys[i].last  = lv;
        }

        if ((now - keys[i].ticks) >= 20 && lv != keys[i].stable)
        {
            keys[i].stable = lv;
            if (lv == 0) keys[i].request = 1;
        }
    }
}
```

**加第三个按键只需在数组里加一行。**

## 9.2 赛前不建议改

**现在的单键够用。重构会引入风险。**

# 第 11 章 常见故障排查

## 11.1 按下去没反应

| # | 检查 | 怎么确认 |
|---|---|---|
| 1 | **PA0 电平会不会变** | 万用表量，按下应为 0V |
| 2 | **按键一端是否接 GND** | 量通断 |
| 3 | **`Key_CheckRequest` 有没有被调用** | Watch 看 `KeyA_Ticks` 是否在变 |
| 4 | **`Key_GetRequest` 有没有被调用** | 断点或加灯 |
| 5 | **消抖逻辑对不对** | 见第 5 章，这是曾经的 bug |

## 11.2 按一次触发好几次

| 原因 | 处理 |
|---|---|
| **消抖阈值太小** | 20 → 30 或 50 |
| **`Key_Request` 没清零** | 检查 `Key_GetRequest` |
| 按键质量差（抖动特别长） | 加硬件 RC 滤波（100nF 电容对地） |

## 11.3 按住不放一直触发

| 原因 | 处理 |
|---|---|
| `KeyStableLevel` 没更新 | 检查第 6.4 节那段代码 |

## 11.4 一上电就触发一次

| 原因 | 处理 |
|---|---|
| 上电瞬间引脚抖动 | 初始化时多读几次，或上电后延时 100ms 再开始扫描 |

# 第 12 章 小结

| 项目 | 内容 |
|---|---|
