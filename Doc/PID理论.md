# 第 0 章 序章：你每天都在用 PID

**洗澡调水温**，就是一个完整的 PID 控制器。

| 你做的事 | 对应 PID |
|---|---|
| 觉得水凉，把龙头往热的方向拧一大截 | **P（比例）**：差多少，拧多少 |
| 拧了还是有点凉，就再一点点继续加 | **I（积分）**：偏差一直存在，就持续加码 |
| 手感觉到水在变热了，提前往回拧一点 | **D（微分）**：看变化趋势，提前刹车 |

- **没有 P** → 你根本不会去拧龙头
- **没有 I** → 水永远差那么一两度（你觉得「差不多了」就不拧了）
- **没有 D** → 你会拧过头，烫一下，再往回调，来回折腾

小车的循迹控制，本质上是同一件事。

# 第 1 章 一步一步「发明」PID

## 1.1 最笨的办法：开关控制（Bang-Bang）

**最朴素的想法**：

```
偏左了 → 右轮加速、左轮减速（使劲掰回来）
偏右了 → 反过来
在中间 → 两边一样快
```

实际会这样：

```
车的位置：中 → 偏左一点点 → 猛掰 → 冲过头到右边 → 猛掰 → 冲回左边 → ...
            ↑                                    ↓
            └────────── 左右画龙 ────────────────┘
```

**为什么？** 因为你只有「全速掰」和「不掰」两档，没有「轻轻掰」。

> 这就叫**开关控制**（Bang-Bang）。空调、电饭煲都用它，因为便宜。但控制精度差，会持续震荡。

**问题根源**：控制力度太粗糙。

---

## 1.2 第一步改进：比例控制（P）

**新想法**：偏得越多，掰得越狠；偏得少，就轻轻掰。

```
输出 = Kp × 误差
```

`误差 = 目标 − 实际`，`Kp` 是你要调的数字。

### 用本车算一遍

方向环：K210 报告线偏了 20 mm，`Kp = 2`：

| 偏差 | 输出（差速量） | 车的行为 |
|---|---|---|
| 0 mm | 0 | 直走 |
| 5 mm | 10 | 轻轻修正 |
| 20 mm | 40 | 用力修正 |
| 50 mm | 100 | 狠狠修正 |

看起来完美了？**不。**

### P 的致命缺陷：永远差一点点

速度环：目标 **40 counts/5ms**，输出是占空比 **0~1000‰**。

假设 `Kp = 20`：

```
第 1 拍：实际 0，误差 40 → 输出 800‰ → 车猛加速
第 2 拍：实际 30，误差 10 → 输出 200‰ → 车减速
第 3 拍：200‰ 只够维持 25，实际掉到 25，误差 15 → 输出 300‰
第 4 拍：300‰ 够维持 30，实际 30，误差 10 → 输出 200‰
第 5 拍：又掉回 25 ...
```

**它在 25 和 30 之间来回抖，永远到不了 40。**

### 为什么会这样

**P 控制有一个内在矛盾**：

> **要产生输出，就必须有误差。**
> **没有误差，输出就是 0。**

而电机**必须有一定占空比才能转起来**（克服摩擦力），所以误差不能是 0。

### 稳态误差有多大

```
实际速度 = 目标速度 × (Kp·k) / (1 + Kp·k)
```

（`k` 是电机增益，例如 100‰ 跑 10 counts/5ms，则 `k = 0.1`）

| Kp | 实际速度（目标 40） | 误差 |
|---|---|---|
| 10 | 20.0 | **50 %** |
| 30 | 30.0 | 25 % |
| 100 | 36.4 | 9.1 % |
| 300 | 38.7 | 3.2 % |
| 1000 | 39.6 | 1.0 % |

**Kp = 10 时，想要 40，永远只跑到 20。**

### 那 Kp 调到 1000 不就行了

**调不到，因为延迟。**

| 环节 | 延迟 |
|---|---|
| 外环采样周期 | 30 ms |
| K210 处理 + 串口传输 | 30~50 ms |
| 内环 5 ms + 电机机械响应 | 10~20 ms |
| **合计** | **~70~100 ms** |

**增益太高 + 延迟 = 自激振荡**（画龙、甩尾）。

```
Kp 上限 ≈ 1 / (k × 延迟) = 1 / (0.1 × 0.08) ≈ 125
```

Kp 到 100 出头就到顶，此时误差还有 9%。

**结论：光靠 P 不行，必须给它加个「记忆」。**

---

## 1.3 第二步改进：积分（I）—— 把欠的账记下来

```
输出 = Kp × 误差 + Ki × (误差的历史累加)
```

### 为什么它能消除误差

```
第 1 拍：累加 = 5     → 额外输出 5Ki
第 2 拍：累加 = 10    → 额外输出 10Ki
第 3 拍：累加 = 15    → 额外输出 15Ki
```

**只要误差还不为 0，累加就会继续涨，输出就会继续加** → 直到误差真的变成 0。

一旦误差到 0，累加就**停在那儿不再变**，输出保持。

> **这就是「记忆」：积分项把「需要多大输出」这件事记下来了。**

### 反证法证明（最漂亮的证明）

假设稳定后误差还是 5：

- 累加就会一直涨
- 输出就会一直涨
- 实际速度就会一直涨
- 误差就会一直变小

**矛盾！** 所以稳定后误差**必然**是 0。

（只要求 `Ki ≠ 0`，与 Kp 大小无关。）

### I 的副作用一：会超调

积分是「慢慢积累」的，它**不知道什么时候该停**。误差变成 0 的那一刻，它**已经积累了很多**。

```
误差：40 → 30 → 15 → 0 → -10 → -5 → 0
输出：       ↑ 积分在这里攒了很多，到 0 时还在推
结果：冲过头，反向修正，再冲回来……震荡
```

工程术语：**积分引入 90° 相位滞后**，让系统更容易不稳定。

### I 的副作用二：积分饱和（Windup）

**场景**：车被手按住，或刚启动。

```
目标 40，实际 0，误差 40
积分器每 5 ms 累加 40
200 ms 后累加 = 1600
输出早就撞到 1000‰ 上限了，但积分器还在涨
```

**结果**：松手瞬间车猛冲 → 冲到 80 → 很花很久才回落。波形上是一个**巨大的超调尖峰**。

详见 [第 3 章 3.4 节](#34-抗积分饱和三种方法详解)。

---

## 1.4 第三步改进：微分（D）—— 学会预判

```
输出 = Kp×误差 + Ki×累加 + Kd×(误差 − 上次误差)
```

### 类比

| 项 | 看的是 | 行为 |
|---|---|---|
| **P** | 现在 | 车偏左 10 cm，往右打 10° |
| **I** | 过去 | 一直往左偏，多打一点 |
| **D** | 未来 | 正在快速回正，快到了，提前回方向 |

**没有 D**：车会**画龙**——冲过中心线，再冲回来，来回摆。
**有 D**：像装了**减震器**，稳。

### 用本车算一遍

方向环，误差从 +10 变到 +5（正在往中心回）：

```
P 项 = Kp × 5        = 正的（还想往右修）
D 项 = Kd × (5 − 10) = 负的（在往回拉，减速）
```

**D 项在「刹车」。** 这就是它抑制超调的原理。

### D 的三个副作用

| 副作用 | 说明 |
|---|---|
| **放大噪声** | 差分 = 高通滤波。误差抖 1，D 项放大 Kd 倍 |
| **微分冲击** | 目标突然变，D 项会产生尖峰 |
| **对采样周期敏感** | dt 变了，Kd 的物理含义就变了 |

详细解法见 [第 4 章](#第-4-章-微分的方法详解)。

# 第 2 章 三个项总览

## 2.1 一张表记住

| | P | I | D |
|---|---|---|---|
| **看的是** | 现在 | 过去 | 未来 |
| **作用** | 快速响应 | 消除稳态误差 | 抑制超调、加阻尼 |
| **副作用** | 稳态误差 | 超调、积分饱和 | 放大噪声、微分冲击 |
| **好比** | 力度 | 记忆 | 预判 |

## 2.2 完整公式

**教科书（连续域）**

```
u(t) = Kp·e(t) + Ki·∫e(t)dt + Kd·de(t)/dt
```

**写代码用（离散域）**

```c
误差   = 目标 − 实际
累加  += 误差
输出   = Kp*误差 + Ki*累加 + Kd*(误差 − 上次误差)
```

## 2.3 什么时候用哪种组合

| 组合 | 适合什么 | 本车用在哪 |
|---|---|---|
| **P** | 简单、允许有误差 | — |
| **PI** | 要消除稳态误差、测量噪声大 | **速度环** |
| **PD** | 不允许超调、不需要消除静差 | **方向环** |
| **PID** | 既要无静差又要低超调，测量干净 | — |

## 2.4 原理框图

```
                    误差 e = 目标 − 实际
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
        ▼                   ▼                   ▼
   ┌─────────┐        ┌──────────┐        ┌──────────┐
   │  P      │        │  I       │        │  D       │
   │ Kp × e  │        │ Ki × ∫e  │        │ Kd × de  │
   │ "现在"  │        │ "过去"   │        │ "未来"   │
   └────┬────┘        └────┬─────┘        └────┬─────┘
        └──────────────────┼───────────────────┘
                           ▼
                    ┌─────────────┐
                    │   求和       │
                    └──────┬──────┘
                           ▼
                    ┌─────────────┐
                    │  限幅       │
                    └──────┬──────┘
                           ▼
                        执行器（PWM 占空比）
```

# 第 3 章 从公式到代码（详解）

## 3.1 位置式 PI —— 速度环（`PID.c:33-80`）

### 完整代码

```c
float PID_V_Calc(pid_velocity_t *pid_v, float actual, float target)
{
    // ① 算误差
    pid_v->err = target - actual;

    // ② 条件积分
    if(pid_v->Ki != 0.0f)
    {
        uint8_t isSatHigh = (pid_v->output >= pid_v->output_max) && (pid_v->err > 0.0f);
        uint8_t isSatLow  = (pid_v->output <= pid_v->output_min) && (pid_v->err < 0.0f);
        if(isSatHigh==0 && isSatLow==0 && fabsf(pid_v->err)<=20)
        {
            pid_v->err_integral += pid_v->err;
        }
    }

    // ③ 积分限幅
    if(pid_v->Ki > 0.0f)
    {
        float integral_max = pid_v->output_max / pid_v->Ki;
        float integral_min = pid_v->output_min / pid_v->Ki;
        if(pid_v->err_integral > integral_max) pid_v->err_integral = integral_max;
        if(pid_v->err_integral < integral_min) pid_v->err_integral = integral_min;
    }

    // ④ 算出输出
    pid_v->output = (pid_v->Kp)*(pid_v->err) + (pid_v->Ki)*(pid_v->err_integral);

    // ⑤ 输出限幅
    if(pid_v->output > pid_v->output_max) pid_v->output = pid_v->output_max;
    if(pid_v->output < pid_v->output_min) pid_v->output = pid_v->output_min;

    return pid_v->output;
}
```

### 执行顺序（不能调换）

```
① 算误差
    ↓
② 累加积分     ← 用【上一拍】的 output 判断饱和
    ↓
③ 积分限幅     ← 必须在 ④ 之前
    ↓
④ 算输出
    ↓
⑤ 输出限幅     ← 必须在返回之前
    ↓
保存到 pid_v->output（供下一拍的 ② 使用）
```

### 两个关键细节

**细节 1：第②步用的是「上一拍」的 output**

```c
isSatHigh = (pid_v->output >= pid_v->output_max) && ...
                     ↑
            这是上一次调用结束时保存的值
```

**为什么？** 这一拍的输出还没算出来（要等第④步）。用上一拍的值是**标准做法**——上一拍饱和了，说明这一拍大概率也饱和。

代码注释已写明：

```c
//  注意：这里判断饱和用的是上一周期的 output，这是标准做法
```

**细节 2：`Ki != 0` 和 `Ki > 0` 的判断不能省**

```c
if(pid_v->Ki != 0.0f)   // 防除零
if(pid_v->Ki > 0.0f)    // 防除法得 inf
```

`Ki = 0` 时 `output_max / Ki` = **无穷大（Inf）**，之后所有比较和计算全部变 NaN。

> **新手常犯：只想着「Ki=0 就是不积分」，忘了除法。**

## 3.2 位置式 PD —— 方向环（`PID.c:108-136`）

### 完整代码

```c
float PID_L_Calc(pid_line_t *pid_l, float err)
{
    // ① 滚动保存误差，首周期特殊处理
    if(pid_l->isFirstRun == 1)
    {
        pid_l->isFirstRun = 0;
        pid_l->err_last = err;          // 首周期：err_last 对齐当前误差
    }
    else
    {
        pid_l->err_last = pid_l->err;   // 正常：err_last ← 上一次的 err
    }
    pid_l->err = err;                   // err ← 本次误差

    // ② PD 输出
    pid_l->output = (pid_l->Kp)*(pid_l->err) + (pid_l->Kd)*(pid_l->err - pid_l->err_last);

    // ③ 输出限幅
    if(pid_l->output > pid_l->output_max) pid_l->output = pid_l->output_max;
    if(pid_l->output < pid_l->output_min) pid_l->output = pid_l->output_min;

    return pid_l->output;
}
```

### 为什么要有 `isFirstRun`

这是**微分冲击**的处理。

**没有它会发生什么？**

上电瞬间：
- `err_last` 初始化为 **0**（`PID_LineLoop_Init`）
- 摄像头第一帧报告误差 **30 mm**
- D 项 = `Kd × (30 − 0) = 30 × Kd`
- 若 `Kd = 5`，D 项 = **150**

而方向环输出限幅是 ±`Speed_Straight` = **±40**。

**150 远超 40，直接顶满** → 上电瞬间差速打满 → 车猛甩。

**加上 `isFirstRun` 后**：首周期 `err_last = 30`，D 项 = `5 × (30 − 30) = 0`，平滑起步。

代码注释：

```c
//(人话:防止上电被D项带着起飞,因为lasterr刚上电为0,差分可能很大)
```

### 方向环为什么没有 I

**方向环的误差理想值是 0（线中心）。**

加 I 会出现：

```
车在弯道内侧待了 500 ms，误差一直是 −15
→ 积分累加到 −15 × 100 = −1500（按 30 ms 一拍算）
→ 出弯后误差回到 0，但积分还在喊「往左打！」
→ 车反向甩出去，再花很久才回来
```

**方向环的偏差是「瞬时几何偏差」，不是「持续性偏置」，所以不需要 I。**

---

## 3.3 一个必须知道的坑：Ki / Kd 里藏着 dt

教科书上 `Ki` 的单位是 `1/秒`。但代码是：

```c
err_integral += err;    // 每周期加一次，没有乘 dt
```

**这意味着 `dt` 已经被吸收进 Ki 了。** `Ki` 的单位是「**每周期**」，不是「每秒」。

**后果**：把采样周期从 5 ms 改成 10 ms，**Ki 必须减半**，否则积分速度翻倍。

> **铁律：改了采样周期，Ki 和 Kd 都要按比例重算。**

---

## 3.4 抗积分饱和：三种方法详解

> **为什么需要抗饱和？** 积分器是「只进不出」的——误差一直存在，它就一直涨，**不管输出是不是早就撞墙了**。

### 方法一：积分限幅（Clamping）

**原理**：直接给积分值画上下限，到线就不许再涨。

```c
if(pid_v->Ki > 0.0f)
{
    float integral_max = pid_v->output_max / pid_v->Ki;
    float integral_min = pid_v->output_min / pid_v->Ki;
    if(pid_v->err_integral > integral_max) pid_v->err_integral = integral_max;
    if(pid_v->err_integral < integral_min) pid_v->err_integral = integral_min;
}
```

**为什么限幅值取 `output_max / Ki`？这是全文件最精妙的地方。**

```
积分项对输出的贡献 = Ki × err_integral
希望：积分项【单独】最大只能贡献到满量程
即：  Ki × integral_max = output_max
所以：integral_max = output_max / Ki
```

**换个说法**：不管 Ki 调到多大，积分项**永远不可能单独把输出顶爆**，它最多只能「独自占满满量程」。

**数值例子**（`Kp = 3.0, Ki = 0.3`）：

```
integral_max = 1000 / 0.3 = 3333
```

误差一直为 40（目标 40，实际 0）时：

| 时间 | 累加值 | 是否被限幅 |
|---|---|---|
| 5 ms | 40 | 否 |
| 100 ms | 800 | 否 |
| 400 ms | 3200 | 否 |
| **420 ms** | **3360** | ✅ 被夹到 3333 |
| 500 ms | 3360 | ✅ 不再增长 |

**效果**：即使误差持续 10 秒，累加值也不会超过 3333。

| 优点 | 缺点 |
|---|---|
| 实现最简单（3 行） | 只能「限制最大值」，不能「提前阻止增长」 |
| 数学上有保证 | 饱和期间积分「记忆」是满的，退出时仍有延迟 |
| 不依赖额外状态 | |

**适用**：几乎所有场合都应有这一层，是**最后一道保险**。

---

### 方法二：条件积分（Conditional Integration）

**原理**：已经顶到限幅了，而且误差还在往同方向推 → 干脆别累加了。累加了输出也加不上去，只会让积分器白白涨得更高。

```c
uint8_t isSatHigh = (pid_v->output >= pid_v->output_max) && (pid_v->err > 0.0f);
uint8_t isSatLow  = (pid_v->output <= pid_v->output_min) && (pid_v->err < 0.0f);

if(isSatHigh==0 && isSatLow==0)
{
    pid_v->err_integral += pid_v->err;
}
```

**四个条件逐个解释**

| 条件 | 含义 |
|---|---|
| `output >= output_max` | 输出已经在正上限，加不上去了 |
| `err > 0` | 误差还是正的（还想加速） |
| `isSatHigh`（两者同时成立） | **别累加了** |
| `output <= output_min` 且 `err < 0` | 负方向同理 |

**关键：只防「恶化」，不防「恢复」**

| 上一拍输出 | 本拍误差 | isSatHigh | 会不会累加 | 说明 |
|---|---|---|---|---|
| 1000（满） | +30 | **1** | ❌ 不累加 | 还在加速 → 防恶化 |
| 1000（满） | **−30** | **0** | ✅ **会累加（负的）** | 反向 → **允许积分退回** |
| 500（未满） | +30 | 0 | ✅ 会累加 | 正常 |
| −1000（负满） | −30 | isSatLow=1 | ❌ 不累加 | 防恶化 |
| −1000（负满） | +30 | isSatLow=0 | ✅ 会累加 | 允许恢复 |

**一句话**：

> **「饱和 + 同向误差」→ 冻结积分**
> **「饱和 + 反向误差」→ 照常累加（积分自动退回）**

**数值例子**（`Kp = 3.0, Ki = 0.3`，目标 40，车被卡住实际 0）

```
第 1 拍：err=40，output=0（初始），不饱和 → 累加 40 → 输出 132
第 2 拍：err=40，output=132，不饱和   → 累加 80 → 输出 144
...
第 N 拍：output 涨到 1000（饱和）
第 N+1 拍：err=40，output=1000，isSatHigh=1 → ❌ 不累加
         输出保持 1000，累加值【冻结】
```

**没有条件积分**：累加值继续涨（每拍 +40），10 秒后 = 80000，`Ki × 80000 = 24000`。松手后要等它降回 3333 才能正常控制，**可能几十秒**。

**有条件积分**：累加值冻在 3333 附近，松手立刻能响应。

| 优点 | 缺点 |
|---|---|
| 防止饱和区积分白白增长 | 需要正确判断饱和方向 |
| 退出饱和响应快 | 用上一拍 output，有 1 拍延迟 |
| 不增加参数 | 只处理「输出饱和」，不处理「误差过大」 |

**适用**：执行器有明显限幅（电机、阀门、加热器）的场合。

---

### 方法三：积分分离（Integral Separation / Gating）

**原理**：误差太大时，根本不积分。因为大误差阶段 **P 项已经足够强**，再加积分只会让超调更严重。

```c
if(isSatHigh==0 && isSatLow==0 && fabsf(pid_v->err)<=20)
                                  ↑
                            误差小于 20 才积分
```

**阈值 20 是怎么定的**

20 是 **counts/5ms**（编码器增量单位）。本车目标速度：

| 速度 | 值 |
|---|---|
| `Speed_Straight` | 40 |
| `Speed_SmallAngle` | 25 |
| `Speed_LargeAngle` | 15 |

**20 ≈ 直道目标速度的 50%**。含义：误差超过目标速度的一半，就认为「这是大偏差，先用 P 猛拉，别让 I 帮倒忙」。

**数值例子：启动过程**（`Kp=3.0, Ki=0.3`，目标 40，实际 0）

**❌ 没有积分分离**

| 时间 | 误差 | 累加值 | 输出 |
|---|---|---|---|
| 0 ms | 40 | 40 | 132 |
| 200 ms | 40 | 1640 | **612** |
| 400 ms | 40 | 3240 | **1000（饱和）** |
| 450 ms（追上） | 0 | **3240** | **972** ← 积分还在大喊加速 |
| 500 ms | −20 | 3240 | **912** ← 冲过头 |
| 600 ms | −40 | 3240 | **792** ← 冲得更远 |

**结果**：冲到 60~70，很久才回落。

**✅ 有积分分离（阈值 20）**

| 时间 | 误差 | 是否积分 | 累加值 | 输出 |
|---|---|---|---|---|
| 0 ms | 40 | ❌ (>20) | 0 | **120**（纯 P） |
| 200 ms | 30 | ❌ | 0 | 90 |
| 300 ms | **18** | ✅ | 18 | **59.4** |
| 400 ms | 10 | ✅ | 28 | **38.4** |
| 500 ms | 2 | ✅ | 30 | **15** |
| 稳定 | 0 | ✅ | 30 | **9** |

**注意最后一行**：误差为 0 时输出 = `Ki × 30 = 9`。这 9‰ 就是**积分器记住的「维持速度所需的输出」**。

**结果：平滑加速，无超调。**

| 优点 | 缺点 |
|---|---|
| 彻底消除启动超调 | **需要根据系统调阈值** |
| 大误差时不帮倒忙 | 阈值太大无效，太小稳态慢 |
| 实现简单 | 阈值和速度量程绑定，改速度要重调 |

**适用**：目标值会大幅阶跃的系统（「直道 40 → 弯道 15」就是典型）。

---

### 方法四（本车未用）：反计算 Back-Calculation

工业上还有第四种，了解全貌即可。

```c
// 伪代码
output_raw = Kp*err + Ki*integral;
output     = clamp(output_raw, min, max);

// 关键：把「超出部分」按系数 Tt 反向扣掉
integral += err - (output_raw - output) / Tt;
```

| | 限幅 | 条件积分 | 积分分离 | **反计算** |
|---|---|---|---|---|
| 思路 | 硬夹 | 冻结 | 关闭 | **反向抵消** |
| 平滑度 | 中 | 中 | 差（突然开关） | **最好** |
| 额外参数 | 无 | 无 | 阈值 | **Tt** |
| 复杂度 | 低 | 低 | 低 | **高** |

**本车不需要**——限幅、条件积分、积分分离三层已足够。

---

### 三种方法对比总表

| | **积分限幅** | **条件积分** | **积分分离** |
|---|---|---|---|
| **代码位置** | `PID.c:52-64` | `PID.c:40-49` | `PID.c:45` |
| **一句话** | 到线就夹住 | 饱和了就冻结 | 误差大就不积分 |
| **防什么** | 积分值无限增长 | 饱和区白增长 | 启动超调 |
| **触发条件** | 一直起 | 输出饱和且同向 | 误差 > 20 |
| **需要参数** | 无（自动算） | 无 | **阈值 20** |
| **副作用** | 无 | 1 拍判断延迟 | 阈值要调 |

### 为什么三种可以叠加

```
        ┌─────────────────────────────────┐
        │  误差 = 目标 − 实际              │
        └────────────┬────────────────────┘
                     ▼
        ┌─────────────────────────────────┐
        │ 【方法三】误差 > 20 吗？          │
        │   是 → 不积分，跳过              │
        └────────────┬────────────────────┘
                     ▼
        ┌─────────────────────────────────┐
        │ 【方法二】输出饱和且同向吗？      │
        │   是 → 不积分，跳过              │
        └────────────┬────────────────────┘
                     ▼
        ┌─────────────────────────────────┐
        │ 【方法一】累加值超限了吗？        │
        │   是 → 硬夹到上限                │
        └─────────────────────────────────┘
```

**三道关卡串联，只要有一道拦住就不会饱和。**

### 各自的「失效场景」

| 方法 | 失效场景 | 后果 |
|---|---|---|
| **积分限幅** | 限幅值设得太大 | 积分仍能涨很高，退出时仍有超调 |
| **条件积分** | 输出没真正饱和（`output_max` 设成 100000） | 永不触发，等于没有 |
| **积分分离** | 阈值设得太大（比如 200） | 永远在积分，等于没有 |
| **全部三种** | **`Ki` 本身太大** | 即使限幅也跟不上，仍会振荡 |

**抗饱和不是万能的，`Ki` 本身必须合理。**

# 第 4 章 微分的方法（详解）

> D 项能加阻尼、抑制超调，但也带来两个新问题：**微分冲击**和**噪声放大**。这一章讲 6 种应对方法。

## 4.1 方法一：标准微分（对误差求导）

```c
D = Kd × (误差 − 上次误差)
```

**教科书写法，也是本车方向环现在的写法**（`PID.c:124`）。

### 优点
- 对设定值变化响应最快
- 代码最简单

### 致命缺点：微分冲击（Derivative Kick）

**目标值可以突变，实测值不能。**

方向环 `Kd = 5`，输出限幅 ±40：

```
上电第一帧，误差从 0 跳到 30
D = 5 × (30 − 0) = 150
```

**150 远超限幅 40 → 直接顶满 → 车猛甩一下。**

本车用 `isFirstRun` 挡住了首帧（`PID.c:112-116`），但如果**目标值在运行中突变**（例如以后加「偏移到赛道某侧」功能），冲击会再次出现。

---

## 4.2 方法二：微分先行（Derivative on Measurement / PI-D）

```c
D = −Kd × (实测 − 上次实测)
```

**把求导对象从「误差」换成「实测值」。**

### 为什么能消除冲击

| 量 | 会不会突变 |
|---|---|
| 目标值 | ✅ 会（按个按钮就跳） |
| 实测值 | ❌ 不会（物理量有惯性，必须连续变化） |

所以对实测值求导，**D 永远平滑**。

### 数学关系

```
误差 = 目标 − 实测
对误差求导 = 对目标求导 − 对实测求导
```

- 目标不变时：`对误差求导 = −对实测求导` → **两者完全等价**
- 目标突变时：`对目标求导` 是无穷大脉冲 → **这就是冲击来源**

### 在本车上是什么情况

| 环 | 设定值 | 结论 |
|---|---|---|
| **速度环** | 会突变（40→25→15） | **但它是 PI，没有 D 项**，不涉及 |
| **方向环** | **恒为 0**（线中心） | `Kd(e−e_last) = −Kd(y−y_last)`，**已经等价于微分先行** |

**本车现在的代码事实上已经是微分先行。**

### 什么时候必须改

**如果给速度环加 D 项。** 速度环目标来自外环，每 30 ms 阶跃一次，是典型的「目标突变」。

```c
// 错误（会有冲击）
pid_v->output = Kp*err + Ki*integral + Kd*(err - err_last);

// 正确（微分先行）
pid_v->output = Kp*err + Ki*integral - Kd*(actual - actual_last);
```

### 代价

**跟踪斜坡设定值会有稳态误差。** 但本车目标是阶跃型（40/25/15 三档），**没有这个问题**。

---

## 4.3 方法三：不完全微分（微分低通滤波）

```c
D_raw = Kd × (误差 − 上次误差)
D     = α × D上次 + (1 − α) × D_raw      // α 取 0.7 ~ 0.9
```

**给 D 项加一阶低通滤波器。**

### 为什么需要

误差的差分 = **高通滤波**，噪声全被放大。

方向环误差来自视觉，30 ms 一帧，**像素级抖动 ±2~3 mm 很常见**：

```
误差序列：+2, −1, +3, +1, −2, +3 ...
差分：    −3, +4, −2, −3, +5 ...
D 项：    Kd × 上面这些抖动
```

**D 项输出全是噪声，不是有效信号。**

### 数值效果（α = 0.8）

| 拍 | D_raw | D（滤波后） |
|---|---|---|
| 1 | 100 | 20 |
| 2 | −100 | −4 |
| 3 | 100 | 16.8 |
| 4 | −100 | −6.6 |
| 5 | 100 | 14.7 |

**尖峰被压掉约 80%，但保留了趋势。**

### 代价
- 引入额外相位滞后（响应变慢）
- α 越大越平滑，但越滞后
- 多一个参数要调

### 本车要不要加

**如果调参时发现「Kd 一大就抖」，就该加。**

判断现象：
- `Kd` 小 → 入弯冲过头
- `Kd` 大 → 车抖得像筛糠
- **中间没有合适值** → 噪声太大，需要不完全微分

---

## 4.4 方法四：微分限幅（Derivative Clamp）

```c
float d = Kd * (err - err_last);
if(d >  D_MAX) d =  D_MAX;
if(d < -D_MAX) d = -D_MAX;
output = Kp*err + d;
```

**单独给 D 项画上限。**

### 为什么需要

整体输出限幅（±40）挡不住 D 项尖峰带来的**方向**问题：

```
P 项 = +5（该往右修）
D 项 = −150（尖峰，往左拉）
输出 = 5 − 150 = −145 → 整体限幅到 −40
```

**结果是「往左打满」——方向完全反了！** 整体限幅只压幅度，**方向仍然错**。

### 建议取值

`D_MAX` 取 `output_max` 的 30%~50%。本车方向环 `output_max = 40`，故 `D_MAX ≈ 12~20`。

### 本车要不要加

**建议加。** 视觉偶尔丢帧或跳变，一个尖峰就能让车甩出去，这是很便宜的保护。

---

## 4.5 方法五：微分死区（Derivative Deadband）

```c
if(fabsf(err) <= 死区) {
    d = 0;           // 误差很小时不加 D
}
```

### 本车已经有了（但是全局死区）

`Service.c:257`：

```c
if(fabsf(error) <= 3) {
    error = 0.0f;   // 忽略细微抖动
}
```

**这是把误差本身清零**，所以 P 和 D 都受影响——效果比「D 单独死区」更强。

| 做法 | 影响 |
|---|---|
| **全局死区**（本车） | P 和 D 都变小，中心附近更迟钝但更稳 |
| **D 专用死区** | 只压 D，P 仍连续 |

**本车这个更适合循迹**：中心附近不折腾，是对的。

---

## 4.6 方法六：多点差分（求平均）

```c
// 两拍差分（本车现在）
D = Kd × (e − e_last)

// 四拍跨度差分（更平滑，但更滞后）
D = Kd × (e − e_前2拍) / 2
```

用更长跨度算斜率，噪声被平均。**代价是滞后。** 外环 30 ms，滞后 2 拍 = 60 ms，**对循迹太慢，不建议**。

---

## 4.7 六种方法对比

| # | 方法 | 核心思想 | 解决什么 | 代价 | 本车 |
|---|---|---|---|---|---|
| 1 | **标准微分** | 对误差求导 | — | 微分冲击 | ✅ 方向环在用 |
| 2 | **微分先行** | 对实测求导 | 微分冲击 | 斜坡有稳态误差 | ✅ 已等价 |
| 3 | **不完全微分** | D 项低通 | 噪声放大 | 相位滞后 | ❌ 可选 |
| 4 | **微分限幅** | D 单独限幅 | 尖峰反向 | 无明显 | ❌ **建议加** |
| 5 | **微分死区** | 小误差不加 D | 噪声放大 | 中心迟钝 | ✅ 已有（全局） |
| 6 | **多点差分** | 长跨度斜率 | 噪声 | 滞后大 | ❌ 不适合 |

## 4.8 给这辆车的建议

| 优先级 | 做什么 | 理由 |
|---|---|---|
| **现在** | 什么都不改 | 方向环设定值恒 0，标准微分已等价微分先行；死区已有 |
| **调参时** | 观察 Kd 大时是否抖 | 抖 → 考虑不完全微分 |
| **赛前可选** | 加微分限幅（`D_MAX = 15`） | 防视觉跳帧导致甩尾 |
| **以后** | 给速度环加 D 时必须用微分先行 | 内环目标每 30 ms 阶跃 |

# 第 5 章 调参手册

## 5.1 顺序：绝对不能跳步

```
第 1 步：内环 Kp（Ki = 0, Kd = 0）
第 2 步：内环 Ki
第 3 步：外环 Kp（Kd = 0）
第 4 步：外环 Kd
```

**内环没调好就调外环 = 在流沙上盖楼。**

## 5.2 每一步的判据

### 内环 Kp

| 现象 | 判断 | 动作 |
|---|---|---|
| 响应慢、软绵绵 | 太小 | 加大 |
| 有小幅高频抖动 | 接近临界 | 回退 20 % |
| 大幅振荡 / 尖叫 | 太大 | 减半 |

**目标**：阶跃响应快速到达、超调 < 10 %、无持续振荡。

### 内环 Ki

从 `Kp/100` 量级开始慢慢加。

| 现象 | 判断 |
|---|---|
| 稳态误差慢慢消失 | ✅ 对了 |
| 缓慢的「呼吸式」振荡 | 太大 |
| 启动冲很高再掉回来 | 积分饱和，检查 `fabsf(err)<=20` |

### 外环 Kp

让车在直道上跑。

| 现象 | 判断 |
|---|---|
| 偏离后回正很慢 | 小 |
| 回正时冲过中心线、来回摆 | 大 / 缺 D |

### 外环 Kd

专门治「画龙」。

| 现象 | 判断 |
|---|---|
| 入弯冲过头 | 小 |
| 车抖动、对视觉噪声敏感 | 大 |

## 5.3 本车起点

```c
PID_VelocityLoop_Init(&pid_v_left,  0, 0, ...);   // Kp=0, Ki=0
PID_VelocityLoop_Init(&pid_v_right, 0, 0, ...);
PID_LineLoop_Init(&pid_l, 0, 0, ...);             // Kp=0, Kd=0
```

**全是 0，车不会动。** 这是刻意留的调参起点。

建议起手值（需上车验证）：

| 参数 | 起手值 | 蓝牙调参上限 |
|---|---|---|
| `pid_v.Kp` | 3.0 | 10.0 |
| `pid_v.Ki` | 0.3 | 10.0 |
| `pid_l.Kp` | 1.5 | 50.0 |
| `pid_l.Kd` | 5.0 | 100.0 |

## 5.4 调参时的观察方法

**一定要看波形调，不要凭感觉。** 看这四路：

| 通道 | 看什么 |
|---|---|
| 目标速度 vs 实际速度 | 跟随快不快、超调多少 |
| 视觉误差 | 车在中心附近抖不抖 |
| 左右目标速度差 | 差速量是否合理 |

# 第 6 章 为什么本车是 PI + PD

## 6.1 速度环为什么不能加 D

| 理由 | 说明 |
|---|---|
| **测量噪声** | 5 ms 内编码器只有几十个 counts，±1 就是 2.5 % 抖动，D 放大它 → 剧烈抖 |
| **目标会突变** | 内环目标来自外环，每 30 ms 跳一次（40→25→15），加 D 会有微分冲击 |
| **不需要** | D 的作用是抑制超调，速度环是「跟随」型，本来就慢 |

## 6.2 方向环为什么不能加 I

```
车在弯道内侧待久了 → 积分累积
出弯后 → 积分还在喊「往右转」 → 反向过冲
```

**方向环的偏差是「瞬时几何偏差」，不是「持续性偏置」，不需要 I。**

## 6.3 串级控制

```
   ┌─────────────────────────────────────────────┐
   │                                             │
视觉 err ─→ [外环 PD, 30ms] ─→ target_left/right │
                              target_left/right │
                                     ↓          │
              [内环 PI, 5ms] ←──── 编码器        │
                     ↓                          │
                  PWM ──→ 电机 ─────────────────┘
```

**外环的输出，就是内环的目标。**

| 环 | 周期 | 管什么 | 反馈源 |
|---|---|---|---|
| 外环（方向） | 30 ms | **往哪走** | 视觉 |
| 内环（速度） | 5 ms | **走多快** | 编码器 |

**内环每 5 ms 就把「速度被扰动了」修好，外环根本看不到这些扰动。**

**频率分离准则：内环比外环快 5~10 倍。** 本车 30/5 = 6 倍 ✅

# 第 8 章 答辩话术

> 我的系统是**串级 PI-PD 结构**。
>
> **内环 5 ms 速度环用 PI**：编码器在 5 ms 内只有几十个 counts，量化噪声大，加微分会放大噪声；且内环目标是外环输出、每 30 ms 阶跃一次，加 D 会产生微分冲击。
>
> **外环 30 ms 方向环用 PD**：视觉误差理想值为零、属于瞬时几何偏差而非持续性偏置，积分会让车过弯后反向过冲，所以不加 I；D 项用于抑制入弯超调。方向环的设定值恒为零，D 项本质上已作用在测量值上，等价于**微分先行**。
>
> **抗积分饱和**用了条件积分、积分分离、积分限幅三重防护，限幅值取 `output_max/Ki`，保证积分项单独最大只贡献满量程。
>
> **频率分离**：内外环周期比 6:1，符合内环比外环快 5~10 倍的工程准则。
>
> **偏置处理**：视觉误差小于 3 mm 时置零，抑制中心附近的像素级抖动，避免 D 项放大噪声。
