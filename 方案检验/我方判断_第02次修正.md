## 1. 我方认错

### 1.1 「1730 里有 41% 在补打滑」——表述错误

**它说得对。** 正确的算法是：

```
实测 1230 counts 只转 64°
转角增益 = 64 ÷ 90 = 71%          → 损失 29%
为补回 90°，计数要放大 1730 ÷ 1230 = 1.41 倍
```

**1.41 是「补偿倍数」，不是「损失占比」。** 我把两件事混成一句话，写成「41% 在被浪费」，这是错的。

**但结论不变**：这个 1.41 是本机本地的系数，换地面就会变。所以决策依据应该是
「这个系数随场地漂」，而不是「41% 这个数」。

**已处理**：评审材料 §7.2 的措辞改掉（见 §6）。

### 1.2 弯的跑动顺序，我没有自己算

它给了 `左直角 → 左钝角 → 顶锐角 → 右钝角 → 右直角`。
我用有向面积独立验了一遍：

```
(124.5,0) → (0,0) → (0,110) → (124.5,266.5) → (249,110) → (249,0) → 回起点
有向面积 = −93748.5（负值 = 顺时针）✓
```

**验算通过。** 而且它自己标注了「方向不确定，但类型序列不变」，这个处理是对的：
我的纯里程方案只认**类型序列** `90 → 39 → 103 → 39 → 90`，不认左右，所以方向不影响方案。

## 2. 接受它的新增

### 2.1 里程现场校核：走 294 cm，读编码器，误差 < 2% 就用

**接受，而且我认为该加一条**：不是只校一次，是**每次铺完布校一次**。

理由：打滑随地面材质变，而 1730（转角）和里程刻度是同一个打滑在起作用。
铺一次布校一次，成本 2 分钟，能同时锁住两个旋钮。

### 2.2 采信 / 存疑 / 反对 的三级表态

这个机制本身有价值——它把「照单全收」和「全盘推翻」两个极端都堵住了。

我同意它的分级结果，除了下面第 3 节那一条。

### 2.3 对 §8.2 / §8.3 两个否决维持不变

「看见新路就停」「偏差归零就停」都已用仿真否掉，它没有翻案。**同意。**

## 3. 保留分歧（1 条，已缩小）

### 3.1 §6 仿真表：不能整表作废，要分列标注

它说「精确角度数字不能当决策依据」。

**我认为这张表的每一列效度不同，不能一刀切：**

| 那一列 | 性质 | 受仿真参数影响 |
|---|---|---|
| 「该转多少度」90 / 39 / 103 | **赛道几何**算出来的 | **不受影响** |
| 「1730 转出 90.2°」 | **定义**：1730 就是照 90° 标的 | **不受影响** |
| 「各种规则在第几度停」 | 依赖「哪些行能认出线」 | **受影响** |

所以正确处理是：**同一张表里把第三列单独标注为「理想仿真，受参数影响」，前两列保留。**

它现在措辞是「趋势可采信」，跟我的立场已经很接近，**不值得再争**。

## 4. 它漏掉的一条（这是本轮最重要的分歧）

### 4.1 两种「用里程」的方案，差一个数量级

**它的方案**：

```
视觉报状态2  →  里程查表决定「该转多少度」  →  转
```

**我的方案**：

```
里程到阈值  →  直接转（角度查表）  →  视觉完全不参与弯道判定
```

**差别不在细节，在「谁来决定开始转」：**

- 它的方案里，**视觉必须报弯**。里程只负责「报弯之后选哪个角度」。
- 我的方案里，**视觉只负责直道巡线**，弯道由里程驱动。

### 4.2 我为什么坚持

1. **「钝角弯报不报状态 2」到现在没有答案。**
   交接文档 §20.2 第⑥条、§20.4 都把它列为未解决的问题。
   如果它不报，它的方案在钝角弯直接跳过 —— 后面全错位。
2. **错位一次就致命。** 序列是 90 → 39 → 103 → 39 → 90。
   如果把「103」当成「39」，少转 64°，车直接冲出去。
3. **里程不依赖视觉**，只依赖「走了多远」，这一条在任何光照下都成立。

### 4.3 它的方案的优势（我承认）

1. 改动小 —— 不用改「何时转」的逻辑，只把角度查表插进去
2. 视觉状态 2 是**真实观测**，能自动对齐赛道上真实发生的事
3. 我的方案怕「起始位置错」和「累计里程漂」

### 4.4 我的折中建议

**两个都用，互相校验：**

- **主**：里程到阈值就转（不依赖视觉）
- **辅**：视觉报弯时，检查里程读数
  - 读数在阈值 ±10 cm 内 → 采纳，正常转
  - 读数离阈值很远（比如 30 cm）→ 说明里程漂了，**以视觉为准**并重置里程
  - 视觉一直不报 → 里程照转，不等待

这样两边互为兜底，且不会因为一方失效就全盘崩。

## 5. 我方新增意见（报告没有）

### 5.1 「钝角弯报不报状态 2」是所有方案的分水岭，必须先查

- **报** → 它的方案可用，我的方案更稳
- **不报** → 只有里程方案能过

查法：读卡器回来后，翻日志看钝角弯那一段有没有出现状态 2。
**这件事不用车、不用摄像头，只要有卡就能做，应该排在所有事情前面。**

### 5.2 摄像头到货第一件事不是改代码，是量三个弯的实测转角

现在三个角度是 90 / 39 / 103。其中 **39° 是我按五边形内角和推的，从来没量过**。

如果它其实是 45°，那所有按比例算的计数（740 / 1980）全错。

**量法**：地上画一条直线，车贴着走，打满差速转到车头对准下一条线，量转过的角度。
一次 10 分钟，三个弯 30 分钟。**这比改任何代码都值。**

### 5.3 三天怎么排（我的建议，和它的不完全一样）

| 天 | 它建议 | 我建议 |
|---|---|---|
| Day 1 | 改五段查表 + 里程触发 | **先量三个弯的真实转角**，再改五段查表 |
| Day 2 | 现场标定三个角度 | 按它的方案跑通（视觉报弯 + 查表），留日志看钝角弯报不报 |
| Day 3 | 联调，钝角优先 | 若钝角弯不报状态 2 → 切到纯里程方案 |

**理由**：Day 1 不量角度就改代码，等于在错误的数上搭架子。而且量角度只用 30 分钟，不影响进度。
