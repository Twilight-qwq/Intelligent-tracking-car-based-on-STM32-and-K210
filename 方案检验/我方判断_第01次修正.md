### 1.9 PD 权限算错了：是 11.17，不是 6.9

**怎么验的**：`Control/AlgorithmLayer/PID.c` 的输出是

```
output = Kp × 偏差 + Kd × clamp(偏差变化量, ±8)
```

- P 项最大：0.231 × 30 = 6.93
- D 项最大：0.53 × 8 = 4.24
- 合计 **11.17**

而 `Service.c:573-576` 的限幅是 `±base_speed`（15/25/30），11.17 不会碰到限幅。

我原文只算了 P 项，**结论「PD 补不动 50°」站不住。采纳。**

### 1.10 「500 毫秒强制直行」才是「少转 + PD 补」的真正杀手

**这条是整份报告最有价值的一条**，因为它解释了一个我一直没想通的矛盾：
为什么「锐角弯少转 13°，实测却是压线、还能自己救回来」，而「少转 50°」就一定救不回来。

报告的算法：

- 少转 50° → `CORNER_HANDOVER_MS = 500` 期间车必须直行
- 500 ms × 42.1 cm/s ≈ **21 cm** 直线前进
- 横向偏移 = 21 × sin50° ≈ **16 cm**
- 车道半宽只有 20 cm → 几乎压线出界，PD 根本还没接管

**采纳。** 这条直接推翻了「永远少转」方案的可行性，除非先把 500 ms 改掉。

## 2. 不采纳

### 2.1 「§6 那张仿真表不能代表当前系统」—— 夸大了

报告说我写的直角 90.2° / 钝角 38.5° / 锐角 103.0° 是「旧参数下的理想世界结果」。

**它把两件不同性质的事混在一起了：**

| 那一列 | 性质 | 受仿真参数影响吗 |
|---|---|---|
| 「该转多少度」90 / 39 / 103 | **赛道几何算出来的**，跟视觉参数无关 | 不受影响 |
| 「1730 转出 90.2°」 | **定义**：1730 就是照 90° 标定的 | 不受影响 |
| 「各种规则在第几度停」 | 依赖「哪些行能认出线」 | **受影响** |

所以正确的处理是：**给那张表加一行「理想无噪声仿真」，而不是作废**。

它唯一说到点子上的子句是「没模拟反光、褶皱、掉帧」——这一句我接受，并且我原来确实没写。

### 2.2 「`ROW_TARGET_CM[0] = 27.5`，和文档的 27.7 矛盾」—— 它判错了

**怎么验的**：

- `ROW_TARGET_CM` 是**目标值**：程序按它去挑最接近的像素行
- 挑到的是第 123 行
- 第 123 行按投影公式算出来的真实距离是 **27.7 cm**
- 串口日志逐行打印的就是「`行123 前 27.7 半 91`」

**目标值 27.5，实测 27.7，两者不是同一个东西。** 同理 45.0/44.6、63.9/64.2、103.0/101.4 都是这个关系。

文档没错，是它把目标值和实际值混为一谈。

## 3. 我方新增（报告里没有）

### 3.1 五边形闭合校验：249.0 + 45.0 = 294.0，差 0.0

报告只说「有五个弯」，**没验证这五个弯能不能拼出一个闭合的形状**。我补了这一步：

```
斜边与竖直方向夹角     = 180° − 141.5° = 38.5°
两条斜边的水平投影     = 2 × 200 × sin38.5° = 249.0 cm
车道中心线底边长       = 249.0 cm
车道中心线到外侧内边缘 = 半车道 20 + 半线宽 2.5 = 22.5 cm
外侧内边缘之间         = 249.0 + 2 × 22.5 = 294.0 cm
用户实测                                  294 cm
```

**差 0.0。**

这说明三件事同时成立：
1. 五个弯的模型对
2. 内角 141.5° 虽然是从内角和推的，但推对了
3. 「294 是从外侧黑线内边缘算起」这个测法，和我理解的 22.5 cm 偏移一致

**这是对整份赛道模型最硬的一次交叉验证，报告没做。**

### 3.2 「里程」不该用来分类，该用来直接决定「什么时候转」

报告提的是：用出弯后的里程**查表判断是哪个弯**，再决定转多少度。
我认为应该再往前一步：**里程直接决定何时开始转，整圈不依赖视觉的弯道判定。**

顺序是固定的：

| 转完这个弯 | 再走多远 | 转下一个弯多少度 |
|---|---|---|
| 直角 | 110 cm | 39° |
| 钝角 | 200 cm | 103° |
| 锐角 | 200 cm | 39° |
| 钝角 | 110 cm | 90° |
| 直角 | 294 cm | 90° |

**为什么这比「靠视觉报弯」更好**：还有一个悬而未决的问题——**钝角弯到底报不报状态 2**。

- 如果不报：任何「等视觉说弯、再查表」的方案，会在钝角弯直接跳过，之后全部错位。
- 用里程：不管视觉报不报，车到 110 cm 就转。

代价是里程误差会累积，起始位置必须固定（起跑线在底部直道正中，天然满足）。

### 3.3 里程方案的两个已知弱点（我自己的判断，不是报告说的）

1. **里程刻度本身还有 15% 的不确定**（0.01402 是理论值，实测 0.01610）。110 cm 差 15% 就是 16.5 cm。
2. **打滑**：驱动轮打滑会让实际走过的路小于里程表。已有一次观测是「指令 45 cm 实际走 28 cm」。

应对：把里程刻度**在赛道上标定一次**（走 294 cm 的直道，看里程表读多少），而不是信理论值或信台架。
